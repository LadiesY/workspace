# 测试程序编写 与 自动测试流程读取 说明

适用软件：PCB 自动测试系统（JC）
版本：v1.0　日期：2026-11-10

## 〇、一分钟看懂

整条链路只有三样东西：

1. **测试程序** —— 一张 7 列的规则表，回答"这块板要读哪些框、哪些脚、测什么"。
2. **引脚结果（pins.json）** —— 视觉启动拍照识别后得到的事实：图上每个框在哪、每个引脚在哪。
3. **点位表** —— 程序与引脚结果相乘算出来的执行清单，14 列，一行 = 测一颗脚。

一句话：**程序规定"读什么"，识别结果说明"有什么"，点位表是两者相乘的结果。**

程序改了、或者重新识别了一次，点位表就跟着重算；不存在"表里 25 行、板子上 30 个脚"这种错位。

## 一、测试程序编写

### 1.1 在哪里写

`02 测试管理` → 左栏「测试程序编写」。

打开路径是"项目 → 编辑 → 写程序"三级：

1. 顶部【打开项目 ▾】选一个已有的项目，或点【新建项目】建一个；
2. 点【编辑项目】解锁 —— 打开的项目默认是**只读**，表格、下拉、增删行全部灰着；
3. 左栏点「测试程序编写」，表格就能写了。

**为什么必须先编辑项目**：写程序会改动这个项目"用哪份程序"，属于改项目，不是看项目。只读状态是给"只想看一眼上次配的是什么"的人准备的，避免误改。

### 1.2 程序属于谁：全局共用，项目只记"选了哪份"

| 东西 | 存在哪 | 谁看得见 |
|---|---|---|
| 程序本体（名字 + 7 列 × n 行） | `data\devices.json` → `test.programs[]` | **所有项目共用一套** |
| 项目选了哪份 | `data\devices.json` → `test.projects[].active` | 每个项目各记各的 |

因此在 A 项目里写好的程序，切到 B 项目照样能在【测试程序名称】下拉里选到；删项目、换保存地址都不会让程序消失。

**为什么这么设计**：一块板怎么测，是"这块板的知识"，不该因为换了个项目文件夹就重新写一遍。项目只记一个名字，重开项目时按它读回来。

### 1.3 七列分别是什么

一行 = 一条规则 = "读哪一类框的哪些引脚、测什么"。

| 列 | 取值 | 含义 | 什么时候要填 |
|---|---|---|---|
| 矩形框 | O / T / C / V / F / L（可手输别的） | 读哪一类框，对应识别结果里的 label | 必填 |
| 识别方式 | 全读取 / 不读取 | 这一行要不要执行 | 必填 |
| 点位范围 | 指定点 / 全部 | 读这颗芯片的全部引脚，还是只读点名的几个 | 必填 |
| 点名范围 | 全部 / 指定 | 该标签下所有芯片都算，还是只算某一颗 | 必填 |
| 点名 | 芯片实例名，如 `L_1` | 只在"点名范围 = 指定"时可填 | 条件填 |
| 点位 | 引脚号，如 `1` / `1-8` / `4,22` | 只在"点位范围 = 指定点"时可填 | 条件填 |
| 测试类别 | V（电压）/ f（频率） | 这一行测什么物理量 | 必填 |

**最容易混的两列**：第 3 列「点位范围」是**模式**（全部还是指定），第 6 列「点位」才是**引脚号**。看错这两列，程序一定写不出想要的结果。

点位列支持的写法：

| 写法 | 含义 |
|---|---|
| `1` | 单个引脚 |
| `1-8` | 区间（也接受 `1~8`） |
| `4,22` | 列举（中英文逗号都行） |
| `1-3,7,10-12` | 混写 |

解析时自动去重、自动升序；认不出来的片段直接丢掉，由保存校验指出"点位那列要写引脚号"。

### 1.4 列与列会自动联动

目的是不让人写出"不读还要填引脚号"这种自相矛盾的行：

| 你选了 | 后面会自动 |
|---|---|
| 识别方式 = 不读取 | 点位范围、点名范围、点名、点位、测试类别 **全部清空并禁用** |
| 点位范围 = 全部 | 点位 清空并禁用 |
| 点名范围 = 全部 | 点名 清空并禁用 |

### 1.5 一条规则在读的时候怎么判定

固定五步，顺序不能反：

1. 「识别方式」是**不读取** → 整行跳过（日志记一句"有 N 行是不读取"）；
2. 按「矩形框」找出图里 label 相同的所有芯片；
3. 「点名范围」是**指定** → 再用「点名」筛到某一颗；
4. 「点位范围」是**全部** → 这颗芯片的全部引脚；是**指定点** → 只取「点位」列写的号；
5. 每颗引脚生成一行点位，带上「测试类别」。

**表里没写到的标签 = 不读**，这是默认行为，不是报错。板子上多出一种新丝印是常态，不该让整份程序跑不起来。

### 1.6 保存时校验什么

点【保存程序】可以正常存进去，但会按行号提示问题：

- 矩形框没填
- 识别方式 / 点位范围 / 点名范围 的值不在约定选项里
- 点位范围 = 指定点，但点位那列没有有效引脚号
- 点名范围 = 指定，但点名那列空着
- 测试类别没选，或不是 V / f
- 整份程序里一行「全读取」都没有

**校验只提示、不当场拒绝保存**。理由很实在：写程序是分批进行的，写一半先存一下很常见；真拦住会逼人去做无意义的填空，反而更容易出错。提示会明确写"跑自动测试前先补上"。

### 1.7 新建 / 保存 / 改名 / 删除

| 操作 | 规则 |
|---|---|
| 新建程序 | 清空表格和名字；此时只是草稿，不进程序清单 |
| 保存程序 | **唯一**把表格写进程序库的动作；保存后才会出现在顶部【测试程序名称】下拉里 |
| 改名 | 直接在名称框改，再点【保存程序】；旧名字会被摘掉，不会留两份 |
| 删除程序 | 二次确认，写明"不可复原"；删完各项目里记着的这份也会一并清掉 |
| 有未保存修改时新建 / 打开别的 | 弹窗问"放弃修改 / 继续编辑" |

两条硬约束：

- **程序名全局唯一**，重名会提示换一个（程序是所有项目共用的，重名无法区分）；
- **空程序不能保存**（至少一行），避免存一份"什么都没配"的程序把自己坑住。

### 1.8 一个完整的例子

假设主板 A 上识别出 T_1、T_2、O_1、F_1 四颗（T 类两颗、O 一颗、F 一颗），希望：

- T 类：两颗芯片的所有引脚都测电压；
- O 类：只测第 1~4 脚，电压；
- F 类：只测 F_1 这一颗的第 2 脚，频率；
- L 类：这块板没有，不读。

就这么写四行：

| 矩形框 | 识别方式 | 点位范围 | 点名范围 | 点名 | 点位 | 测试类别 |
|---|---|---|---|---|---|---|
| T | 全读取 | 全部 | 全部 | | | V |
| O | 全读取 | 指定点 | 全部 | | 1-4 | V |
| F | 全读取 | 指定点 | 指定 | F_1 | 2 | f |
| L | 不读取 | | | | | |

展开结果（假设 T_1 有 12 脚、T_2 有 12 脚、O_1 有 8 脚、F_1 有 4 脚）= 12 + 12 + 4 + 1 = **29 行点位表**。

## 二、自动测试怎么读

### 2.1 三个前提

| 前提 | 在哪里满足 | 不满足时 |
|---|---|---|
| 已打开项目 | 自动测试页项目卡【打开项目 ▾】 | 点位表 0 行，日志提示"还没打开项目" |
| 项目选了测试程序 | 测试管理页【测试程序名称】下拉 | 0 行，提示"还没选测试程序，去测试管理选一份" |
| 项目里有 pins.json | 视觉启动完整跑过一轮 | 0 行，提示"还没有 *_pins.json" |

注意是**项目**记着选了哪份程序，自动测试页没有"选程序"的入口 —— 两处各选一份只会互相打架。

### 2.2 pins.json 从哪来

来源就是自动测试页左侧那条流程：

```
点【视觉启动】
  ① 建会话目录（<板号>.<检修状态>.<序号> + 四个子目录）
  ② 3 秒倒计时（让人把手从台面收回来）
  ③ 相机抓一帧 → 存进「相机照片」
  ④ YOLO 识别矩形框 → 画在画布上
  ⑤ 引脚识别 → 红点 + 编号画在画布上
  ⑥ 人工检查、改框改点
  ⑦ 点【保存】→ 写 引脚json\<图名>_pins.json
```

落盘位置：

```
<项目保存地址>\<板号.检修状态.序号>\引脚json\<图名>_pins.json
```

结构（节选）：

```json
{
  "image": "capture_20261110_102233.png",
  "chips": [
    {
      "id": "T_1",
      "label": "T",
      "box": [[812, 240], [1180, 620]],
      "pins": [{"idx": 1, "x": 852.4, "y": 286.1, "side": "top"}]
    }
  ],
  "project": "主板A测试",
  "program": "主板A程序",
  "board": "N",
  "repair": "修前",
  "task": "N.修前.5",
  "saved_at": "2026-11-10 10:22:33"
}
```

自动测试只用 `chips` 这一段：

| 字段 | 用来对程序的哪一列 |
|---|---|
| `label` | 矩形框 |
| `id` | 点名 |
| `pins[].idx` | 点位 |
| `pins[].x` / `y` | 点位表的"像素 Y1 / 像素 Z1" |

`project` / `program` / `board` / `repair` / `task` 这几个键只是方便事后追查"这份结果哪来的"。

### 2.3 什么时候会重算点位表

点位表是**算出来的**，不落盘。这五个时机各重算一次：

1. 打开或切换项目；
2. 每次切回自动测试页；
3. 点【保存】写完 json；
4. 视觉启动跑完一轮；
5. 从相机实时画面切回识别图。

省算力的两个细节：

- 状态没变（还是同一个项目、同一份 json）就直接返回，不重复解析、不刷日志；
- 判断"文件有没有变"用的是修改时间 + 文件大小，不是每次把全文读一遍。

### 2.4 多份 pins.json 时取哪一份

在项目保存地址下**往下三层**扫描所有 `*_pins.json`（再深就不属于本次测试的目录了），取**修改时间最新**的那一份。

取最新而不是"当前会话"，是因为同一块板可能识别过好几次；点位表要反映手上这张图，而不是一个空目录。找不到新的时会沿用上一次那份。

### 2.5 筛点的算法

```
对程序里的每一行：
    识别方式 = 不读取           → 跳过
    图上没有这个 label          → 记进"缺席"清单，跳过（不算错）
    点名范围 = 指定             → 只留 id 等于点名的芯片
                                  找不到 → 记一条警告
    点位范围 = 全部             → 这颗芯片的全部引脚
    点位范围 = 指定点           → 解析点位列，取这些号
                                  图里没有这个号 → 记一条警告
    每颗引脚                    → 生成一行点位
```

结果分三类：

| 结果 | 内容 | 性质 |
|---|---|---|
| 点位 | 真正的执行清单 | 正常 |
| 警告 | 点名找不到、引脚号不存在 | **真出错**，日志按"程序第 N 行"标出 |
| 缺席 | 程序里配了、这张图上没有的标签 | 不是错，可能这块板没上这类件，只列出来方便扫一眼 |

### 2.6 顺序为什么是 S 型

规则表只决定"读不读、读哪些脚"，**不决定先后**。真正的顺序按框在**图上的几何位置**排：

1. 按框的上边从上到下扫描，**纵向有重叠的算同一条带**（不是按固定行高等分）；
2. 带内按中心 x 排序；
3. 第 0 带从左到右、第 1 带从右到左，交替进行；
4. 没有矩形框的芯片排在最后；
5. 同一颗芯片的引脚仍按引脚号升序，**不为了蛇形把一颗芯片的引脚打散**。

三个原因：

- **按 json 数组排不行**：那是 YOLO 这一帧的检出先后，同一块板测两次顺序都不一样，行程无法复现。
- **按类别排不行**：T → O → F → L 会让人在板子两头来回跳，空跑距离最大。
- **分带不能按固定行高**：同一块板上框高能差十倍（实测 F 类 242 px、V 类 20 px、T 类 128 px）。按"中位数 × 0.75"当行高，明明压在一条水平线上的三颗会被拆成三行，蛇形就退化成来回折返。

用"y 区间有重叠就算一条带"，才是按实际版图分带。

### 2.7 点位表 14 列

| 列 | 来源 | 现在有没有值 |
|---|---|---|
| 框名 | `chips[].id` | 有 |
| 点位 | `pins[].idx` | 有 |
| 像素 Y1 | 引脚的 x | 有 |
| 像素 Z1 | 引脚的 y | 有 |
| 空间 u / v | 像素→空间标定换算 | — |
| 控制器 Y2 / Z2 | 像素→机台换算 | — |
| 探针v Y3 / Z3 | 探针坐标换算 | — |
| 探针f V / W | 探针坐标换算 | — |
| 测试 | 程序的「测试类别」 | 有 |
| 结果 | 跑完写 PASS / FAIL | 空 |

**像素列为什么叫 Y1 / Z1 而不是 x / y**：沿用机台坐标系的叫法 —— 图上的 x 就是 Y1，图上的 y 就是 Z1，跟后面控制器、探针那几列排在一起才对得上号。

### 2.8 日志怎么读

正常一次会说两句：

```
点位表已展开：25 行 / 6 个框（T_1 12、T_2 12、O_1 1），规则「主板A程序」4 行 ← xxx_pins.json
  行走顺序按几何 S 型：从上到下分带，带内一左一右交替，尽量少空跑。
```

四类附加信息，按要不要处理分开看：

| 日志 | 含义 | 要不要处理 |
|---|---|---|
| 程序第 N 行：图里没有点名「L_1」 | 程序点名了，图上没这颗 | **要**：改程序，或确认识别漏了 |
| 程序第 N 行：T_2 没有 9 号引脚 | 程序写了图里不存在的脚号 | **要**：改点位 |
| 程序里配了、这张图上没有的框：L（跳过） | 整类都不在 | 一般不用，确认没上这类件即可 |
| 程序里有 2 行是「不读取」，已跳过。 | 正常 | 不用 |

### 2.9 边界与异常对照

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 点位表 0 行 | 没项目 / 没选程序 / 没 json | 看日志那行提示，三种分别对应 2.1 的三条 |
| 行数比预期多很多 | 用了"全部"范围，把新检出的小框也算进来了 | 收窄成「点位范围 = 指定点」或「点名范围 = 指定」 |
| 换项目后表没变 | 两份程序规则恰好一样，或新项目没选程序 | 看日志里的规则名对不对得上 |
| 同一颗芯片出现两次 | 两行都命中同一个 label（比如一行全部、一行指定点） | 合并成一行 |

## 三、现在做到哪一步

| 环节 | 状态 |
|---|---|
| 程序编写、程序库、校验、联动 | 已在用 |
| 点位展开、S 型排序、14 列表格 | 已在用 |
| 逐点执行（走轴、读电压 / 频率、判 PASS/FAIL） | **还没接** |

所以现在的点位表表示的是"**算出该测什么**"，还不是"**测完了什么**"。点【自动运行】目前只写一行日志"功能还没接上"，不动轴、不写结果列；空间 / 控制器 / 探针三类列，也要等标定和控制器接上才有值。

## 四、常见问题

1. **程序为什么是所有项目共用？**
   一块板怎么测是这块板的知识，不该因为换了项目文件夹就消失。项目只记"上次选的是哪份"。

2. **改完程序要重新做视觉启动吗？**
   不用。程序变了只影响规则，点位表重算即可；只有识别结果变了（换了一块板、重拍过）才需要重新启动。

3. **改引脚算不算改程序？**
   不算。引脚是识别结果（pins.json），程序是规则（devices.json），两者独立。改引脚只是在改"这次图上这些脚在哪"。

4. **程序里写了图上没有的框，会报错吗？**
   不报错。跳过，并列进"缺席"清单，日志说一句。

5. **图上有的、程序没写，会读吗？**
   不会。默认不读，这是故意设计的。

6. **点位写 `1-8` 但芯片只有 6 个脚？**
   有值的进表，多出来的号记一条警告，不影响其余点位。

7. **同一颗芯片能不能测两种类别？**
   能。写两行，一行 V 一行 f，点位不同即可。

8. **顺序能不能手动调整？**
   不能。程序只决定"读不读、读哪些"，先后由几何位置自动定，保证同一块板每次行程一致。

9. **程序名能带空格吗？**
   能，但不能和其他程序重名（全局唯一）。

10. **识别结果换了，旧的 json 会删吗？**
    不会。每次识别各写一份，旧的留在目录里备查，点位表只取最新的那份。

## 五、数据落盘位置

| 内容 | 位置 |
|---|---|
| 程序库（所有程序） | `data\devices.json` → `test.programs[]` |
| 项目（含选的程序、板号、检修状态） | `data\devices.json` → `test.projects[]` |
| 引脚识别结果 | `<保存地址>\<板号.检修状态.序号>\引脚json\<图名>_pins.json` |
| 点位表 | 不落盘，每次现算 |
