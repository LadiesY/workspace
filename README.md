# 电路板测试系统

整合五个自研工具（三轴控制、探针、相机、引脚识别、坐标转换）的上位机软件。

**当前版本 v0.3.0 —— 8 个模块：首页（宣传）、设备管理（含运动控制）、测试管理、
自动测试、视觉定位、数据管理（仅布局）、知识库、系统管理（登录 / 角色权限 / 审计 / 备份）。**
八个模块都有真实界面；「数据管理」只做布局、不接采集数据，「自动测试」的运行链路
还没上真机联调。
「运动控制」已并进「设备管理」，作为该页顶部的第二个子页签（2026-11-09 定）。

---

## 一、怎么启动

双击 **`启动电路板测试系统.bat`**

不弹黑色命令行窗口，直接出界面。首次启动约 2–3 秒。

如果双击没反应，看 `data\startup.log`，最后几行会写清楚是哪个环节出的问题；
或者双击 **`诊断启动.bat`**（带控制台跑，报错直接留在窗口里）。

### 打包发给别人

```bat
runtime\python\python.exe tools\build_release.py            :: 只生成文件夹
runtime\python\python.exe tools\build_release.py --zip      :: 顺带压一个 zip
```

产出在 `..\发布\电路板测试系统_v0.2\`（整个文件夹拷过去就能双击启动），
`--zip` 会顺手压一个同名的 zip（1.1 GB → 约 400 MB）。

包里**不带** `data\devices.json`（对方的项目、程序从空白开始），但**带** `data\kb\`
—— 知识库的资料清单、片段索引、资料原件都在，打开就能查，不用重新导入。
运行环境、板卡 DLL、相机 SDK、YOLO 权重也都在，对方不用装 Python、不用联网。

包里的三个 bat：`启动电路板测试系统.bat`（正常启动，无黑窗）、
`环境自检.bat`（离线自检 18 项：解释器 / 依赖 / Qt 插件 / 板卡 DLL / 知识库检索 /
data 可写）、`诊断启动.bat`（带控制台启动，排查用）。

打包时踩过三个坑，都写在 `tools/build_release.py` 顶部注释里：

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 bat 报 `xxx was unexpected at this time`，一行都没执行 | bat 存成 UTF-8 又写了 `chcp 65001`，cmd 按 936 拆字节，长中文注释把一行拆成了两条命令 | bat 用 **GBK** 存盘，不加 `chcp`；注释写英文 |
| 双击后毫无反应、不报错也不退出 | 安装路径**含中文**时，PyQt5 从 DLL 位置推算 Qt 插件目录会把中文变成 `?`（`D:/PCB/??/...`），平台插件加载不到，`QApplication()` 构造直接卡死 | `main.py` 和启动 bat 都显式设 `QT_PLUGIN_PATH` 指向包内插件目录（Qt 用 UTF-8 读这个变量，中文路径没问题）。**裸跑 `python.exe xxx.py` 不设这个变量同样会卡死**（退出码 127、无任何输出），写调试脚本时要记得 |
| 第一次双击等了一分多钟才有窗口 | 1.2 GB 文件刚落地，杀毒软件在逐个扫描；冷读磁盘也慢 | 程序本身 5 秒内就建完窗口（`startup.log` 有 `window shown` 时间戳）。已在「使用说明.txt」写明第一次慢、别连点 |

## 三、设备管理（已接入）

顶部横着排一排设备清单（绿点＝已连接、红点＝未连接），下面是选中设备的参数。
清单横排而不是竖排，是为了把整块横向空间让给相机的实时画面。

| 设备 | 通讯 | 可调参数 |
|---|---|---|
| 三轴控制器 FMC4030 | TCP，默认 192.168.0.30:8088 | X/Y/Z 每轴正负限位、速度、加速度、减速度 |
| 探针座 GAS 卡 | 网口或串口，默认 192.168.0.200 卡号 1 | 六轴 X/Y/Z/U/V/W 的正负限位、速度、加速度、减速度，脉冲当量 |
| 工业相机 海康 MVS | GigE / USB3，按枚举序号选 | 曝光、增益、帧率、分辨率、开窗偏移 |

探针座是六轴卡：轴号 1~6 依次是 X/Y/Z/U/V/W（来源 `TZ\probe\probe_config.json`
的 `axis_u=4 / axis_v=5 / axis_w=6`）。界面上 X/Y/Z 与 U/V/W 用一条
「UVW 第二组平面轴」的标题分开，两组独立配置、互不影响。

三轴 / 探针的参数区是左右两栏：左栏通讯参数 + 参数说明，右栏轴参数表。
探针比三轴多三行，所以轴参数表的表头把单位并进了列名（`正限位 mm`），
省下的一行正好让六行全放得下，不用滚动。

**参数默认是只读的**，点【编辑】才能改，点【保存】才写进 `data\devices.json`；
下次启动读的就是保存后的值。编辑时点【取消】丢弃改动。

### 相机的实时画面

相机连上后，设备页左侧会直接显示采集画面 —— 调曝光/增益要看着画面调才有意义。

- 画面框按**传感器长宽比**摆放（默认 3:2，对应 3072×2048），整幅画面刚好填满框、
  不变形、不留黑边；改了 ROI/分辨率后框的比例跟着真实帧自动变
- 画面是自己画的（不走 SDK 的 `DisplayOneFrame`），所以能缩放：**滚轮缩放**、
  缩放后**按住左键拖动**平移到想看的区域、**双击**回到整幅适配
- 底部状态条（浮在画面下沿，不占画面高度）：分辨率 · 实时帧率 · 当前缩放比例
  （100% = 1 屏幕像素对 1 传感器像素）
- 缩放放大时用最近邻取样，放大后每个传感器像素边界清清楚楚，不会被插值糊掉
- 取流跟页面走：选中相机且已连接才开始；切走或断开自动停（相机不被白占）；
  右上角【停止取流 / 开始取流】可以手动开关
- 相机掉线（拔线、断电）会自动停下来并松掉句柄，日志里写原因
- 改分辨率/开窗偏移时相机会拒绝，所以保存时自动「停流 → 下发 → 续流」；
  曝光、增益、帧率是实时改的，画面不会中断
- 选中相机时底部的运行日志会自动折叠成一行，把高度全让给画面；
  点【展开】可以再铺开（手动展开后就不再自动折叠）

保存时如果设备已连接，会顺手把参数下发：
- 探针：把六轴的 mm 限位换算成脉冲写进卡（`GA_SetSoftLimit`，逐轴下发）
- 相机：把曝光/增益/帧率/分辨率写进相机
- 三轴：限位是**软件限位**（运动指令下发前比对目标位置，超限不发指令），速度与加减速随每条运动指令走，没有「写进控制器」这回事，所以只需要保存

**参数默认值不是编的**，来自三个原工具的配置：

| 来源 | 取用内容 |
|---|---|
| `KZQ\config.json` | IP 192.168.0.30、端口 8088、速度 50、加减速 20、限位 35/180/200 |
| `TZ\probe\probe_config.json` | 地址 192.168.0.200、卡号 1、脉冲当量 12800、v_xy 2.0、a_xy 500 |
| `XJ\config.json` | 曝光 330000 µs、增益 0 dB、帧率 3.03 fps |

### 连不上时先看日志

设备面板底部有运行日志，失败原因会写在那里，比如：

- `连接失败：连接失败（查网线 / IP / 端口，必要时重启控制器）`
- `控制器无响应：Open 返回成功但读不到版本信息` —— 这是 20240920 版 DLL 与固件不匹配的典型症状，换 20210906 版
- `未发现相机：…GigE 相机要与本机网卡同网段…`

三轴的 DLL 内部 TCP 超时比较长，IP 不通时会静默等十几秒，12 秒时会先给一句提示，不是卡死。

### 三条规则：点了才存、点了才能改、删了不可复原

| 动作 | 什么时候能点 | 说明 |
|---|---|---|
| 💾 保存项目 | 只有编辑状态 | **只有它会把项目写进清单**。新建时填名字、选地址都只是草稿，`打开项目` 里看不到 |
| ✎ 编辑项目 | 项目已保存、且现在只读 | 打开的项目默认**只读**；点它才解锁名称、地址、浏览、yolo 模型和【测试程序名称】下拉 |
| 🗑 删除项目 | 项目已保存 | 弹窗确认，写明"删除后不可复原"，确认后回到空白页 |

三个按钮在**项目信息条的第二行右侧**（原来挂在左栏底下）：它们管的是整个项目，
跟项目名称、保存地址放在一起才顺；左栏只留"有哪两块"。

- 新建 → 可编辑 → 点【保存项目】→ 进清单、转只读；
- 打开 → 只读 → 点【编辑项目】→ 改 → 点【保存项目】→ 又转只读（编辑期间按钮显示"编辑中"并置灰）；
- 编辑中途去【新建项目】或打开别的项目，会先问一句"还有没保存的修改"，
  不会悄悄丢掉；
- 删除只从清单里移除，保存地址里的照片、引脚 json、日志、结果**一个都不动**。

两个入口（测试程序编写 / 坐标转化）左边各配了一个图标：`program` 是编号步骤列表，
`calib` 是准星 —— 见 `app/icons.py`，选中时变强调蓝。

### 项目 = 名字 + 保存地址 + yolo 模型

- 【新建项目】：点了之后下面才出现「项目名称」「保存地址」两行。名字空着也行，
  选完文件夹会按文件夹名自动填。
- 【打开项目】：下拉列出**本机保存过的项目名字**（不是选文件夹），地址不在的项目
  后面标「保存地址不存在」。
- 保存地址**只**决定自动测试的照片、引脚 JSON、日志、结果存哪，不往里写任何项目文件。
- **yolo 模型**：这个项目做引脚识别用哪个模型文件（`.pt` / `.onnx`）。不同板子训出来的
  模型不一样，所以它跟着项目走，不是全局设置。选完要点【保存项目】才记住。
  跟保存地址一样，**只读时是灰的**，点【编辑项目】才能换；文件被挪走或删掉时，
  路径框会标成红字，鼠标停上去写明"这个文件不在了"。
- **三轴 X 粗定位（mm）**：第三阶段自动测试开跑时，三轴控制器的 X 轴先移到这个位置，
  把板子送到相机视野附近，再交给视觉细定位。**范围由设备管理里 X 轴的正负限位决定**
  （默认 ±35），旁边直接写着允许区间；填超了当场退回原值并提示，也不许保存 ——
  存个越界值进去，等到自动测试时驱动层拒动，反而更难查。设备管理里把限位设成 0
  （＝不限）时这里显示"不限"。
- **探针 XYZ / UVW 步长**：探针两组轴走小步时用多大一步（mm）。给了一列常用值
  （0.001 ~ 5），也可以直接手填；必须是大于 0 的数字，否则不许保存。

项目清单存在 `data\devices.json` 的 `test.projects`（有序列表，下拉顺序＝新建顺序）：

```json
{"name": "主板 A 测试", "root": "D:\\TestProjects",
 "created": "2026-11-05 10:12", "active": "主板A程序",
 "yolo": "D:\\model\\best.pt",
 "x_coarse": 12.5, "step_xyz": 0.02, "step_uvw": 0.005,
 "program": {}, "calib": {}}
```

`active` 是这个项目**上次选中的测试程序名**，打开项目时按它把程序读回来；
`yolo` 是模型文件的绝对路径（空串＝还没选）；`x_coarse` / `step_xyz` / `step_uvw`
就是上面三项测试参数，`null` 表示还没设；`calib` 是坐标转化的标定参数
（下一轮往里填）；`program` 是老版本存程序的地方，现在空着 —— 程序搬进了全局库
`test.programs`（见下）。

**为什么不像上一版那样在保存地址里放 `project.json`**：保存地址可能是个公共结果目录、
共享盘，甚至别人机器的盘符 —— 往里塞配置文件容易被清掉、被同步走。项目清单属于
"这台机器装了哪些项目"，和硬件参数放一起最省事；地址失效了，项目名还在下拉里，
重新指过去就行。

地址没了不影响打开，状态条标成 `● 地址失效`，点【编辑项目】重新选一个就好
（这里刻意**不会**替你把目录建出来）。

### 每次自动测试建一个会话目录

自动测试（功能模块 4）开跑之前调一次 `Project.ensure_session()`，它返回本次目录：

```
D:\TestProjects\                  ← 保存地址（你在【新建项目】里选的）
    N.修前.1\                     ← 每次自动测试一个：板号.检修状态.序号
        相机照片\
        引脚json\
        日志\
        测试结果\
    N.修前.2\                     ← 同板号同状态第二次
    N.修后.1\                     ← 修后从 1 重新数（两条线各数各的）
```

- 名字格式 `板号.检修状态.序号`，三段用点隔开；序号 = 同板号同状态已有的最大号 + 1；
- 没填板号**不建目录、不让启动**（2026-11-09 起取消时间命名兜底）；
- 序号不复用：删掉中间某一号，下次仍按最大号 + 1；
- 四个子目录跟着一起建好，各环节只管往里写。

地址下面那行小字实时算"下次会建哪个目录"，右边显示"已有 N 次记录"；
`_clock` 每 20 秒刷一次，页面开着也不会停在过时的路径上。

### 测试程序 = 一张 7 列 n 行的规则表

点左栏「测试程序编写」，右栏就是这张表。一行 = 一条"读哪类矩形框的哪些引脚、测什么"：

| 列 | 取值 | 意思 |
|---|---|---|
| 矩形框 | O / T / C / V / F / L + 新增类别（可手输） | 芯片标签，对应 `pins.json` 里 `chips[].label` |
| 识别方式 | 全读取 / 不读取 | 这类标签读不读；不读取就整类跳过 |
| 点位范围 | 指定点 / 全部 | 所有引脚都读，还是只读后面点名的几个 |
| 点名范围 | 全部 / 指定 | 该标签下所有芯片都算，还是只算点名的那个 |
| 点名 | `L_1` | 芯片实例名，对应 `chips[].id`；只在"点名范围=指定"时填 |
| 点位 | `1` / `1-8` / `4,22` | 引脚序号；只在"点位范围=指定点"时填 |
| 测试类别 | V / f | V=电压、f=频率 |

两个「点位」列是唯一容易混的：第 3 列是**模式**，第 6 列才是**引脚号**。界面上
第二列名字已经区分成「点位范围」和「点位」。

**列之间会互相清空**，省得写出自相矛盾的行：`识别方式=不读取` → 后面五列清空并禁用；
`点位范围=全部` → 点位清空；`点名范围=全部` → 点名清空。

**表里没出现的标签默认不读取**，不报错（板子上出现新丝印是常态）。

**「矩形框」列的候选与「视觉定位 → 类别管理」同步**（`program.label_hints()` 每次现算）：
内置 6 类在前、新增类别按名称接在后面，下拉里每一项还挂了悬停说明
（"Y　任意朝向两排 · 14 脚/排 · 共 28 点"），填的时候不用回视觉页确认它几脚。
增删在**回到本页时**生效（`TestPage.showEvent` → `ProgramEditor.refresh_labels()`），
所以老程序不用重开。

- 只刷**候选项**，不碰单元格里的字：删掉一个类别，程序里已经填的 `Y` 不会被清掉，
  那份程序照样能打开、能存（只是运行时读不到这类框，等于整行跳过）
- 备注里那一串标签也是现算的，新增的类别会被点名标出来
- `program.validate()` **不校验**标签是否在候选里 —— 板子上出现没登记过的丝印是常态，
  不该让整份程序存不下去

程序条：`新建程序` → 起名字、点【新增行】加规则 → 【保存程序】→ 才会出现在项目信息条上的
【测试程序名称】下拉里。`删除程序` 有二次确认；**项目只读时表格整块是灰的**，
跟项目的只读规则一致。

**程序是全局的**，不挂在某个项目下 —— 存在 `test.programs`
（`[{"name", "created", "rows": [{…7 列…}]}]`）。在哪个项目里写好的程序，换到别的项目
也能在下拉里选到；删项目不会把程序带走。老版本把程序存在
`project.program["programs"]` 里，启动时自动搬进全局库（重名加 `(2)` 后缀）。

### 打开哪份程序：项目条上的【测试程序名称】

- 下拉一行一份程序，选中后右栏表格**自动读取**那份程序（不用再点打开），旁边跟着注明几行；
- 刚打开项目、刚选程序的表格都是**只读**的：只能看，要改先点【编辑项目】；
- **下拉本身也受只读约束**：打开项目后它是灰的、点不开，点【编辑项目】才解锁 ——
  "这个项目看哪份程序"算改项目，光看的话打开时已经把上次那份读进来了；
- 选「（未选择程序）」等于把表格收起来，有没保存的改动会先问一句；
- 保存 / 改名 / 删除程序之后下拉立刻跟着变，不用重开项目；
- 表格条上原来那个【打开程序 ▾】并到了这里 —— 两处放一模一样的下拉只会让人犹豫点哪个；
- **选过就记住**：选中的程序名写进项目的 `active`，下次打开这个项目直接把它读回来，
  不用再选一遍（选完立刻写配置，不等【保存项目】）。

### 表格怎么变成点位：`app/program.py`

```python
points, warns, absent = program.resolve(chips, rows)
#  chips  ← *_pins.json 里的 chips
#  points → [{row, chip:"L_1", label:"L", idx:1, x:178.5, y:123.1, side:"top", category:"f"}]
#  warns  → [(行号, "图里没有点名 L_2")]     真出错
#  absent → ["O","T"]                        表里配了、图上没这类件（正常，不算错）
```

`program.validate(rows)` 在保存后给一句体检结果（缺点位、缺点名、类别不合法…），
**只提示不拦保存** —— 编到一半先存下来是常态，跑自动测试前再补。

实测（拿 `D:\207\shujuji` 下的真实数据跑的）：

| 图 | 读到的点位 |
|---|---|
| `1_pins.json`（T_1，20 脚） | 1-8 号共 8 点 |
| `2_pins.json`（O_1 / O_2） | 各 1 号，共 2 点 |
| `8_pins.json`（L_1，6 脚） | 1 号 1 点；L_2 那条报"图里没有点名" |
| `F\2_pins.json`（F_1 128 脚 / C_1 / V_1） | F 取 4、22；V 取全部 2 点；C 整类不读 |

### 为什么是"左选项、右内容"，而不是把两块上下排

「测试程序编写」是 7 列表格，「坐标转化」是标定参数表 + 残差图，两个都要横向空间，
窄栏里就废了。所以左边只放"有哪两块"，右边整块留给编辑区 ——
和视觉定位页"左参数右画面"是同一套路。

## 五、自动测试（项目卡 + 画面 + 点位表 + 日志）

左侧导航第 4 项。整板自动测试最终按流程跑：X 轴粗定位 → 取图识别 → 坐标换算 →
探针测试 → 出结果。目前做完的是**画面区**（画布 450×300 + 引脚编辑条）、
**项目卡**、**右栏的 14 列点位表**、**页面底部的运行日志**、**急停**，
以及 **【视觉启动】（建目录 → 3 秒 → 拍照 → YOLO → 引脚识别）** 和
**【保存】（人工确认后写 `引脚json` 并展开点位表）**。
**【自动运行】还没接**（用户指定：先不接）。

**界面上没有单独的状态行、日志区也没有【复制】【清空】按钮**（两处都按用户
要求删掉了）：一切提示只走日志，想复制就用鼠标选中日志文字后 `Ctrl+C`。

画布是**固定 450×300**（图像 1 px = 屏幕 1 px，不跟窗口缩）。一列里
"卡片 133 + 画布面板 358 + 日志"共 651 px，752 px 的页面放得下，
所以项目卡留在左上。**画布高度超过约 380 px 时卡片就得让位**（674×450 那次
被迫挪到右栏，一列要 898 px 放不下）。

窗口矮到画布放不下时（<约 700 px 高的页面），`_fit_canvas()` 会把画布压矮
（最低 180），不会让画布和下面的引脚编辑条叠在一起；窗口回到正常高度又是
450×300。

- **打开项目**：下拉列的是**测试管理里保存过的项目**（同一份 `test.projects`）。
  选完把整份项目读进来（保存地址、上次选的程序、yolo 模型、X 粗定位、探针步长），
  最后一条日志说明"读到了什么、缺什么"——比如"保存地址不可用""还没选测试程序"
  "yolo 模型文件不在了"。项目在测试管理里改名/删掉后，切回本页会自动重读。
- **三个状态点**：跟设备管理同步（`device_changed`），本页**不提供连接/断开**。
  绿=已连接、红=未连接、橙=连接中，鼠标停上去有状态文字；**状态变化会记一行日志**。
- **画面区**：用的是「视觉定位」页那两个控件的**同一份代码**
  （`vision.canvas.InteractiveCanvas` + `vision.pinedit.PinEditKit`），不是另抄一遍，
  所以缩放 / 平移 / 选点 / 画框的行为两边永远一样。画布尺寸固定 450×300，
  图像在里面按比例 fit，不会变形；引脚编辑条用 `compact=True`（去掉标题和
  召回率读数，最小宽 503→381，450 放得下）。**视觉启动之后这条工具条就是真能用的**：
  拖角点改框、右键改标签名 / 删框、画笔补点、删除选中、撤回、召回率，全都落到
  `_chips` 上并同步写回 json。
- **运行日志**：整页最下面那条（约 3~5 行高，跟着窗口伸缩），`_say()` 说什么它就记什么
  （带时间戳 + 级别），另外设备连上/断开、打开项目、按钮点了也各记一行。
  最多留 800 行，超了丢最老的，要往前翻就滚。
- **右栏 14 列点位表**：就是「运行点位」那张表的样子（框名 / 点位 / 像素 Y1·Z1 /
  空间 u·v / 控制器 Y2·Z2 / 探针 v Y3·Z3 / 探针 f V·W / 测试 / 结果），
  一行 = 一个要测的引脚，只读。**表头常驻**：一进页就有 14 列，没数据就是 0 行。
  行是**按程序算出来的**，不是抄表（见下节）。
  **14 列一屏看全**：表头写成两行（"控制器 / Y2"），行号列不要了，1280 及以上的
  窗口正好铺满、没有横向滚动；列头带 tooltip 写全含义。
- **视觉启动**：见下节「视觉启动：一次点击做完五件事」。
- **保存**：人工检查过才点 —— 写 `引脚json`，再按项目程序展开点位表。见「保存：人工确认之后才落盘」。
- **自动运行**：只有按钮，点了会明说"功能还没接上"（同时进日志）。按用户要求先不接。
- **急停**（项目卡最右边那颗红按钮，和三个业务按钮隔开 40 px）：
  按下 = 立刻停 + 上锁，再按一次 = 解除。它永远可点，设备没连上也照样按得下去；
  **正在跑的视觉流程会同时被中止**（相机一停流就等不到帧了，与其挂 8 秒超时不如当场收掉）。
### 视觉启动：一次点击做完五件事

实现在 `app/vision/session.py`（`VisionSession`），页面只负责把信号接到日志和画布上。

```
点【视觉启动】
  ① 建会话目录   <保存地址>\<板号.检修状态.序号>\ + 四个子目录（没填板号不让启动）
  ② 3 秒倒计时   画布左上角浮层显示"3 / 2 / 1 秒后自动拍照"
  ③ 拍照         相机取流抓一帧 → 相机照片\capture_20261106_174205.png
  ④ YOLO         项目选的模型（没选就用自带 best.pt）→ 矩形框画在画布上
  ⑤ 引脚识别     对上面那些框找引脚 → 红点 + 编号画在画布上，然后交给人检查
```

### 板号：项目卡第一行右侧那个输入框

填这一块板的编码（`PCB-2026-1109-03` 这种），**回车即存** —— 进 `data\devices.json`
的 `test.projects[].board`，下次打开项目自动回填，不用每次重填。它是本次测试目录名的
**第一段**：

```
目录名 = 板号 . 检修状态 . 序号        例：N.修前.5
```

| 情况 | 目录名 | 说明 |
|---|---|---|
| 板号 N、修前，一次没跑过 | `N.修前.1` | 序号从 1 起 |
| 已经跑过 `N.修前.1` ~ `N.修前.4` | `N.修前.5` | 取**最大序号 + 1** |
| 同板号换修后 | `N.修后.1` | 修前 / 修后**各数各的** |
| 没填板号 | 不建目录、不让启动 | 日志提示"先填板号"，不再退回时间命名 |

序号**不复用**：把 `N.修前.3` 删掉，下次仍然是 5（按现有最大号往下走），免得纸质记录 /
已归档的结果和后来那一次撞号。用点不用横杠，是因为板号自己很可能带 `-`
（`PCB-2026-1109-03`），横杠连着写分不清哪段是分隔符。

输入时会清洗：`\ / : * ? " < > |` 这些 Windows 不允许的字符换成下划线，连续空白收成
一个，首尾的空格和点去掉，最长 32 字。清洗结果会**回显在输入框里**（存成什么看得见），
日志再说一遍本次目录名。Tooltip 里直接写出"本次测试目录会叫什么"。

板号是**项目的属性**，和保存地址、yolo 模型一样跟着项目走 —— 不另存成保存地址里的
一个文本文件（那样换个地址就丢了）。写 `引脚json\*.json` 时也带一份 `board`，方便查。

**为什么没另起一行**：左栏高度是卡死的（画布固定 450×300）。卡片再高 14 px，画布在
1380×840 还能保住 300，但 1280×800 就会从 279 掉到 265 —— 那就成了"别的区域变了"。
所以板号放进第一行项目名右边那段空地，尺寸一像素没动。

### 检修状态 / 任务号：项目卡第二行

原来这一行是「● 三轴控制器 ● 探针座 ● 工业相机」三个设备状态点。2026-11-09 按用户
要求把设备状态**搬到页头右侧**（和「04 自动测试」同一水平线），腾出来的这一行放两项：

| 控件 | 取值 | 怎么来 | 落在哪 |
|---|---|---|---|
| 检修状态 | 修前 / 修后（默认修前） | 选中即存，没有"确定" | `devices.json → test.projects[].repair` |
| 任务号 | `N.修前.5`（只读） | **自动算**：同板号同状态已有目录的最大序号 + 1 | 不落盘；写进 `引脚json\*.json` 的 `task` |

任务号就是**本次目录名**，不是另填的编号 —— 所以它不能手改（框是只读的，能选中复制）。
板号回车、检修状态换值、打开项目这三个时机重算一次；真开跑时 `ensure_session()` 会
再算一次（界面显示 5、期间别处先建了 5 就顺延到 6），绝不往已有目录里写。

两项都是**项目的属性**，和板号一样打开项目就回填、跟着项目走；写 `引脚json\*.json`
时会各带一份 `repair` / `task`。检修状态还用在哪：同一块板返修前后各测一遍，靠它区分
两批数据，也靠它把序号分成两条独立的线。

尺寸账：第二行从 16 px 的文字行换成 22 px 的下拉框 / 输入框，多出的 6 px 由"行距
12→10、下边距 12→10"抵掉，**卡片仍是 136 px**，画布 450×300 一点没变。

页头的设备状态是**自绘页头里的一块子控件**（不是布局项）：坐标由 `_place_devbar()`
按标题行中线现算，窗口一 resize 就重摆；绘制标题时可用宽度会让开它，窄窗口下副标题
不会钻到「工业相机」底下。

##### 下拉框箭头

这套 QSS 里 `QComboBox::drop-down` 只定了宽度、没定箭头，Qt 画的默认箭头颜色不受控。全局改会影响别的页，所以只在检修状态这个框上叠了一个字面 `▾`
（跟【打开项目 ▾】同一个字符），对鼠标透明，点哪儿都照样展开下拉。


会话目录长这样（`project.ensure_session()` 建，四个子目录名字是用户定的）：

```
D:\PCB\测试\
    N.修前.5\                  ← 目录名 = 板号.检修状态.序号（同板号同状态第 5 次）
        相机照片\     capture_20261106_174205.png     ← 第 ③ 步
        引脚json\     capture_20261106_174205_pins.json ← 点【保存】才写
        日志\         视觉流程.log                     ← 每步一行，含失败原因
        测试结果\                                      ← 等自动运行接上再写
```

**进度是估算的，不是假进度**：两段识别各是**一次推理**（YOLO 一帧 3~9 秒；引脚识别
一次吃完所有框，`cross_chip` 默认开着，拆成逐个芯片跑会改结果），算法层没有中间
回调。所以进度条按**已经过去的时间**往上爬（实测常数：YOLO 约 1.6%/120 ms ≈ 7 秒），
封顶 95%，真出结果时跳 100%。这样不会出现"卡在 99% 不动"的假象。

**没接相机也能跑通**：`_from_sample()` 会退到离线样图 —— 先看环境变量
`PCB_SAMPLE_IMAGE` 指的图片，再看 `data\samples\` 里最新的那张。用了样图会在日志里
**明说"本次用离线样图（虚拟测试）"**，绝不假装相机拍到了。两处都没有就明确报
"相机未连接，也没有离线样图"，不留半截结果。

**等帧不阻塞主线程**：相机出帧在取流线程，主线程用 100 ms 的 QTimer 轮询"有没有新帧"，
8 秒不来就报超时。阻塞写在主线程会让窗口假死，而这 8 秒里用户可能正想按急停。

**上一轮的结果会被丢掉**：每次 `start()` 给会话一个 `token`，识别结果回来时对不上
就丢弃 —— 防止"连点两次，第二张照片被第一张的框覆盖"。

### 保存：人工确认之后才落盘

识别完**不写文件**是刻意的：YOLO 偶尔多框 / 少框一颗，引脚算法遇上丝印反光也会错，
框错了后面每条运动指令都照着错坐标走。所以中间必须留一道人的眼睛 ——
这时画布下方的编辑条全部可用（拖角点 / 右键改标签 / 画笔补点 / Ctrl+Z 撤回）。

人工改的每一步都会**立刻写回** `引脚json\<图名>_pins.json`（编辑条提示"已同步 …"），
不然关掉就白改了。点【保存】是**确认**：

1. 再写一次 json（`image` / `chips` / `project` / `program` / `saved_at`）；
2. 把这份 json **直接喂给点位表**（`_load_points(path, force=True)`），不靠"找最新文件"猜；
3. 按项目当前选的测试程序展开成 14 列的行，日志里报"点位表已展开：N 行 / M 个框（T_1 8、…）"。

保存之后再改框，表会停在旧结果 —— **要再点一次【保存】**才同步（`_saved` 标记会复位）。

### 切换：识别图 ↔ 相机实时画面

编辑条最右边那颗【切换】（`btn_switch`）管画布显示什么：

| 时机 | 画布 | 【切换】 |
|---|---|---|
| 视觉启动前 / 识别中 | 空提示 / 照片逐步画出来 | 灰的（**保存前不能切**） |
| 点【保存】成功 | **自动**切到相机实时画面 | 亮起 |
| 点【切换】（实时中） | 回到识别图（框 + 红点 + 编号原样） | 仍然亮 |
| 点【切换】（图片中） | 再切实时 | 仍然亮 |
| 重新【视觉启动】/ 离开本页 | 回图片 / 停流 | 回到灰的 |

几个刻意的取舍：

- **实时时不叠识别框和红点**：那些是这张照片的像素坐标，画在动着的画面上会被
  当成"在跟踪"，反而误导。切回图片由 `_paint()` 原样恢复。
- **实时时编辑条锁住**（`PinEditKit.set_locked()`）：画笔 / 矩形框 / 删除选中 /
  撤回 / 召回率全部按住，入口也判 `_locked` —— 画布的 `Ctrl+Z`、`Delete` 走
  `keyPressEvent`，不经过按钮，必须在这层挡，否则会在动着的画面上把照片坐标改坏。
  **注意不能整条 `setEnabled(False)`**：Qt 的禁用向下传播，会把同一排的【切换】
  一起按死，实时画面就退不回来了 —— 所以只按编辑类按钮。
- **帧率**：3072×2048 @30fps 逐帧转 `QPixmap` 是几百 MB/s，界面会卡；最多
  90 ms 刷一次、中间只留最后一帧（和视觉定位页同一套做法）。
- **相机没连 / 被占着**：保存照样成功，但画布留在识别图，日志写"切不了实时画面：
  相机没连上…"，【切换】仍可点（点一下会再试一次并说明原因）。
- **掉线**：自动退回识别图并写日志；**离开本页**退出实时且只停"本页自己开的流"
  （流是别的页面开着的就只断信号，不关别人的）。

### 点位表怎么来的

右栏那张 14 列的表，**行是算出来的，不是从 xlsx 抄的**：

* **规则**来自功能模块 3 保存的程序（7 列：矩形框 / 识别方式 / 点位范围 /
  点名范围 / 点名 / 点位 / 测试类别），项目当前选的是哪份就用哪份；
* **坐标**来自 `*_pins.json`（视觉识别结果，`chips[].pins[].idx/x/y`）；
* 两者交给 `program.resolve(chips, 程序各行)` 展开 —— 这个函数一直写着没人用，
  就是留给自动测试的。上一轮生成「运行点位」xlsx 用的是同一套规则，已核对：
  **25 行逐行一致**（框名、引脚号、像素 XY、测试类别全对得上）。

顺序按**最终图片的几何位置做 S 型**（`program.snake_rank`，2026-11-06 定）：

1. 先用**「y 区间重叠」**把框分成横带 —— 不能用固定行高。同一块板上框高能差
   十倍（实测 F 242px / V 20px / T 128px），拿中位数×0.75 当行高，中心 y 差
   150px 的三颗明明压在一条水平带上会被拆成三行，蛇形就退化成来回折返；
2. 带内按中心 x 排，第 0 带左→右、第 1 带右→左、交替 —— 带与带之间不空跑回最左；
3. 同一个框内引脚号升序 —— 一颗芯片的引脚必须连续测完，不能为蛇形把引脚打散。

为什么不用另外两种顺序：按 **json 数组**走等于看 YOLO 这一帧先检出谁，同一块板
两次跑都不同；按**程序里的类别先后**走会在类别之间来回大跳（实测同一块板
T→F→T→L→C 比 S 型多走 8%，类别交错多的板子差距更大）。

规则表只决定"读不读 / 读哪些脚"，**不决定先后**；S 型里排到但程序判「不读取」
的框会被跳过，不会因为排进队就被测。**json 本身不重排** —— 落盘的是识别 +
人工编辑的原样，顺序是读表那一刻按几何现算的，所以改顺序规则不用重写历史文件。

14 列里目前只有 **框名 / 点位 / 像素 Y1·Z1 / 测试** 有值。空间 u·v、控制器
Y2·Z2、探针 Y3·Z3·V·W 都要等标定与坐标换算（第三阶段），先填「—」占位 ——
留白看不出是"还没算"还是"程序漏了"，所以用破折号；结果列等真跑完才写 PASS / FAIL。

**表头是常驻的**：打开这一页就是 14 个列头，没数据就是 0 行（框名空着）——
用户要的是"一进来就看到流程长什么样"，所以这里**没有空态占位、也没有载入按钮**。

### 14 列怎么挤进一屏

原来 14 列一行铺开要 792 px，右栏只有 590，只能横向滚。现在做了三件事：

1. **表头折成两行**："控制器 Y2" → "控制器 / Y2"。Qt 的 `QHeaderView` 天生不换行
   （`CE_Header` 画文字一律单行加省略号），所以 `WrapHeader` 自己画：先让样式把
   底色和分隔线画好（`opt.text = ""`），再按两行居中把字画上去。表头高 34 px。
   **画字必须单独一段 `painter.save() / restore()`**：样式画完 section 之后
   QPainter 的状态（裁剪区、画笔、字体）不一定还是进来时那份，紧接着 `drawText`
   会被整个吃掉 —— 第一版上线时"表头一个字都没有"就是这个原因，不是字体问题。
2. **行号列不要了**：一行就是一个引脚，序号没意义，白白占掉 38 px（截图里左上角
   那块空格就是它）。
3. **列宽现算**：两行表头里最长那行 + 这一列当前最长的数据，再按剩余宽度等比放大。
   所以现在还是「—」的空列先窄着，等标定接上、真有数字了自己撑开。

效果（默认 1380×840）：14 列总宽 574 = 视口宽，**一条横向滚动都没有**。
1280 也全显示；1100 这种最小窗口右栏只剩 294 px，数字真放不下，退回列宽下限
并横向滚动 —— 宁可滚，也不把列压到看不清字。

列宽是跟着**视口**（`eventFilter`）算而不是跟着页面 `resizeEvent`：滚动条一出现
视口就窄 14 px，跟着页面算会永远差一条滚动条的宽度，右边挂着一小截横向滚动。

数据来源：`项目保存地址里最新的 *_pins.json`（视觉按 `<项目>/<会话>/引脚json/`
落盘，往下找三层，同一块板识别过多次取最新）。打开项目、切回本页都会自动重算，
同一份文件（路径 + 修改时间没变）不重复解析、也不重复刷日志。
没项目 / 没程序 / 没识别结果时，表照旧摆着（0 行），原因只记一行日志。

### 急停到底做了什么

一颗按钮，三层动作，顺序不能反：

1. **置闸** —— `DeviceManager.estop_flag` 和两台驱动的 `_estop` 一起置上；
2. **下发停止** —— 三轴 `stop_axis`（立即停止 + 减速停止各发一遍，再补 Stop_Run）、
   探针 `GA_Stop(0xFF)` 六轴、相机 `stop_stream`；
3. **上锁** —— 按钮变成「↻ 解除急停」（描边款），此后 `move_abs / move_rel / home`
   三个入口全部先过 `estop_block()`，一律拒绝，直到有人明确解除。

为什么必须上锁：只发一次停止挡不住后面的指令 —— 自动流程里的下一条会把轴再带走，
**停完又走等于没停**。两台设备的回零轮询都认这道闸：探针走
`home_full(abort=...)`，按下就 `HomeStop` 退出，实测 0.14 s 打断；三轴 `home()`
每 50 ms 看一次 `estop_active`，按下就补一条立即停止再退出。都不用干等超时。

为什么直接在主线程发、不排队：排在一个 120 秒的回零后面等就不叫急停了。
DLL 的停止调用只有几毫秒，界面这几毫秒不刷新值得。

**没连上的设备会在日志里明说"停止指令发不出去，请按硬件急停"**，绝不假装停了 ——
软件急停永远只是硬件急停的补充，不是替代。

画布**固定 450×300**（`CANVAS_W/CANVAS_H`，`setFixedSize`），左栏 = 450 + 面板
内边距 16 = 466；右栏吃掉剩下的宽度（1380 窗口下 622 px）。
画布下面那条引脚编辑条用 **compact 模式**（`PinEditKit(..., compact=True)`）：
去掉「引脚编辑」标题和召回率读数，最小宽度从 503 降到 381，450 宽的画布放得下。
日志高度**跟着窗口算**，不写死：`_fit_log()` 只改**上限**（页高 15%，夹在
72~112 px，约 2~4 行），下限留 72 px。窗口高就给 4 行、窗口矮收到 2 行。
（用 `setFixedHeight` 改高度会把当前高度变成布局的最小高度，窗口一矮就压不下去。）
页面最小尺寸 **667×708**（窗口约 913×796），1100×700 的最小窗口下也放得下。


## 六、运动控制（已并入设备管理，子页签）

不再是左侧导航里独立的一项。进「02 设备管理」后，页头有两个页签：
**设备管理 / 运动控制**，点一下就在同一块工作区里换内容，左侧导航不用来回跳。

这一页只管「让轴动」，参数怎么改还是切回「设备管理」页签改，两边不重复。

顶部两个块切换设备（三轴控制器 / 探针座）。每块左边一个状态点（绿＝已连接、
红＝未连接、黄＝连接中），右边一行小字说明当前能不能操作。

**这一页不提供连接/断开按钮** —— 连接是设备管理的职责，两处都能连迟早会出现
「这边断了那边还以为连着」的糊涂账。要连设备就切到左边的「设备管理」页签，
连上之后这里的状态点自己变绿、按钮自动可点。

两个子页签是同一个模块的两半：参数在左、动作在右，状态点永远在同一屏，不用记
「刚才是在哪一页连的」。切走时运动控制会停掉轮询线程，切回来再自动接上。

下面的轴表一行一轴：

| 列 | 说明 |
|---|---|
| 轴 | X/Y/Z，探针多 U/V/W 三行 |
| 当前位置 | 200 ms 轮询卡上读回来的实际位置，不是指令回执 |
| 当前速度 | 同上，运动中是青色 |
| 目标位置 | 填绝对坐标，回车或点【移动】走过去；**超出限位会被拦下**（框标红、日志说明） |
| − / + | 按当前步长走一格（相对点动） |
| 移动 | 按目标位置做绝对定位 |
| 回零 | 朝**该轴设定的方向**找原点，完成后坐标清零（两台设备都逐轴可设，见下面【回零设置】） |
| 状态 | 已回零 / 未回零 / 运行中 / 限位 / 报警 |

底部：全部回零 · 回零设置 · 全部停止 ······ ■ 急停，下面是运行日志。

### 几条刻意的做法

- **连接入口只有一个**（设备管理页）。这一页只用状态点和一行文案告诉你连没连上，
  未连接时所有动作按钮都是灰的、点了只会往日志里写一句「先切到【设备管理】页签连接」。
- **速度、加减速不在这里另开输入框**，直接用「参数配置」里每轴的值。两处各存一份
  迟早会不一样，到时候按哪个走谁也说不清。
- **点动步长按设备分别记**，改完 600 ms 后写进 `data\devices.json`，下次启动还在。
  输入框旁边有 0.01 / 0.05 / 0.1 / 1 / 10 五个快捷键。
- **探针没回零不给绝对定位**：没有原点，绝对坐标只是个数字，照着走可能直接撞上去。
  点动不受这个限制 —— 撤出来永远允许。这条可以用 `probe.require_home` 关掉。
  三轴没有这个限制（原工具就是直接走绝对坐标的）。
- **目标位置不许超出「设备管理」里设的限位**，三轴和探针都一样。拦两道：
  界面上点【移动】时先比一次（超了目标框标红、日志写清超了多少，指令根本不提交），
  驱动层 `move_abs` / `move_rel` 再比一次（那道才是防线，别的调用方绕不过去）。
  点动按「卡上读回的当前位置 + 步长」比，到边就整步不走，不会停在限位外。
  目标框空着时直接显示这条轴的范围（如 `-35 ~ 35`），鼠标停上去也有说明；
  设备管理里改了限位，200 ms 内这里跟着变。
  - 三轴：填 `0` 表示该方向不限制（KZQ 原配置语义）
  - 探针：留空表示该方向不限制（原配置是 null），保存时换算成脉冲下发进卡
- **急停是两态**（`jog_panel._on_estop`）：按一次 = 停 + 上锁，按钮变成「↻ 解除急停」；
  再按一次才解除。
  - **停**：先把队列里还没执行的指令清空，再调 `DeviceManager.estop()`，三轴 / 探针 /
    相机一起停。台阶是整机一个闸（`_estop` 事件），自动测试页和运动控制页两块面板
    共用它，一边按了另一边也显示已上锁。
  - **上锁**：闸置上之后 `move_abs / move_rel / home` 全被 `estop_block()` 拦住；
    正在跑的回零轮询里 `abort` 立刻生效，不用等满超时。轴表按钮同时变灰。
  - **解除**：只解闸。**不续跑、不补动作** —— 轴停在哪儿就是哪儿。队列里被清掉的
    指令已经丢了，卡上走到一半的定位也不会自己走完。原因很实在：它为什么停、停在哪、
    有没有丢步，这三件事你都不知道，让它自己接着走是最危险的。
  - **解除后仍显示未回零**：急停会把 `_home_lost` 置上，`read_state` 里把卡上的
    `HOME_SUCESS` / `HOME_DONE` 位和它取与。步进被硬停可能丢步，卡上的位却不会清，
    光看卡会以为「还是好的」。所以必须重新回零一次——探针会**拦住**绝对定位，
    三轴只是状态显示变「未回零」（它没有 `require_home` 那道闸，原工具就没有）。
  - 三轴：三轴各发一次立即停止 + 减速停止，再 `Stop_Run`
  - 探针：`GA_Stop(0xFF, 0)` 一次停六轴
- **一台设备一根线程**（`devices\runner.py`）。状态轮询和运动指令在同一个线程里串行跑，
  不并发调 DLL —— KZQ 那边实测过，轮询线程和点动线程同时调 `get_pos` 会偶发读回 0。
  指令排队执行，执行完一条发一条回执到日志。
- 回零是阻塞的（探针默认超时 120 s、三轴 30 s），回零过程中按急停能立刻打断。
  **回零中途停了又没报成功，2 秒内就判失败**（探针 `gas.home_wait`、三轴 `motion.home`）——
  没有这条判据时会一路白等到超时，日志最后还写着「尚未回零」，看日志的人
  会以为它一直在走。三轴原来只下发不等结果，「全部回零」瞬间返回、日志写「3 轴完成」，
  实际只是「已下发」；现在改成下发后真的等 `HOME_DONE`（或 `HOME_OVERTIME`），
  三根轴**依次**回，不是同时点着。
- 探针的软限位在保存参数时逐轴下发进卡；**回零完成后会再下发一次**收紧限位
  —— 回零前限位是松弛的，不然撞不到负限位开关。

### 【回零设置】（两台都逐轴可设）

「运动控制 → 探针座 / 三轴控制器」的动作条上各有一个【回零设置】。两台的**口径不一样，对话框也是两套**，别看串：

| | 探针座（GAS 卡） | 三轴控制器（FMC4030） |
|---|---|---|
| 方向编码 | 0 = 负向、1 = 正向 | **1 = 正限位、2 = 负限位**（SDK 常量） |
| 速度 | 快移 / 定位 两档 | 回零速度 一项，独立于点动速度 |
| 加减速 | 固定（默认 500 mm/s²） | 逐轴可设，默认 100 mm/s² |
| 脱落距离 | 无（`offset` 是原点偏移，不是这个） | **有**：回零完成后反向退多少 mm |
| 超时 | 默认 120 s | 默认 30 s |

两边都一样的一条：**回零是单向的**。只朝选定方向走，撞到该侧开关就停；走不到就一直顶，
顶到电机堵转、超时为止，全程不报错。所以方向选错不会有任何提示，现场表现就是「电机
一直嗡嗡响、轴顶在尽头」。

#### 探针座（逐轴回零方向）

| 项 | 说明 |
|---|---|
| 回零方式 | 1 = 只找 HOME 开关（默认）；2 = HOME + 编码器 Z 相；3 = 只找 Z 相 |
| 快移 / 定位 | 找开关时的速度 / 找到后二次定位的速度，mm/s |
| 超时 | 单轴回零最多等多久（默认 120 s） |
| 各轴方向 | X/Y/Z/U/V/W 各自一个下拉：负向 / 正向 |

**为什么方向必须逐轴给**：六个轴的方向本来就不一样，原工具
（`TZ\probe\probe_config.json`）里 **X 是 0（负向）、其余五轴是 1（正向）**。
之前这里只有一套 `dir=1` 套六个轴，X 就是朝反方向回零。

落到配置里是 `data\devices.json` 的 `probe.home.dirs`。老文件（只有一套 `home.dir`）
在 `store.load()` 时自动迁移：补出 `dirs`（X 负向、其余正向），把老的 `dir` 丢掉。

#### 三轴控制器（逐轴四项）

| 项 | 默认 | 说明 |
|---|---|---|
| 回零方向 | 负限位（2） | 1 = 正限位、2 = 负限位。默认守住本机原工具一直在用的负向 |
| 回零速度 | 50 mm/s | 厂家上位机默认值；**与点动速度分开**，点动改快不影响回零 |
| 回零加减速 | 100 mm/s² | 厂家示例脚本（指令 260）用的值 |
| 脱落距离 | 5 mm | 厂家上位机默认。回零完成后反向退 5 mm 把开关松开 |
| 超时 | 30 s | 本软件最多等多久；卡上另有「回零超时时间」，谁先到算谁的 |

**脱落距离为什么不能给 0**：轴会停在开关仍被压住的位置，限位输入一直是有效，
状态列就显示「负限位」而不是「已回零」，看着像没回成。厂家默认 5 mm 就是这个原因。

**方向为什么默认不是厂家的 1**：厂家上位机界面的出厂默认是 1（正限位），但那是它的
出厂值，不是本机的机械事实。这台机器的原工具（KZQ）一直用负限位、现场也是这么装的，
照抄厂家默认会把能用的配置改成不能用的。换机器先确认原点开关在哪一侧再改。

落到配置里是 `data\devices.json` 的 `motion.home.axes.{x,y,z}`。老配置没有这一段时，
`store.load()` 按默认值补齐，不用手工改文件。

改完**先只回一根轴试方向**，别直接点【全部回零】—— 多根轴同时跑，反的那根会把
时间全耗在顶死上。

### 首次上机请注意

- 探针 **U/V/W 三轴原工具标注「没在真机上跑过」**，第一次动请单轴、低速、小步长试方向。
- 三轴 / 探针的限位、速度都取自原工具配置（见上表），换机器先改参数再动。
- 位置、速度都是**轮询值**，不是插补轨迹；屏幕上跳字说明卡上真在走。

### 几条刻意的做法

- **识别前必须先把画面拍成照片**：一帧 3072×2048 的识别要几秒，边取流边算的话，
  结果画在 A 帧上、屏幕上已经是 B 帧，框会「飘」到别处去。取景状态下【运行】
  【引脚识别】是灰的，`_guard()` 也会拦下来并说明原因。
- **拍照即落盘**：拍到的不是内存里的临时帧，而是一个真文件 —— 这样补点 / 改框才能
  写回同目录的 `<图名>_pins.json`，也才能用「上一张 / 下一张」翻回来再看。
- **识别跑在后台线程**（`vision\engine.py`，一条队列 + 一根线程串行）：界面不假死，
  连点两下也只会跑一遍；模型加载与三种识别不会撞在一起（torch 推理不保证线程安全）。
- **相机帧合并刷新**：最多 90 ms 刷一次画面，中间只留最后一帧。30 fps 的 GigE 相机
  逐帧转 QPixmap 是 500 MB/s 的搬运，不合并界面会卡。拍多张时画布不刷（停在刚拍的
  照片上），但最新帧照样缓存，下一次拍拿到的一定是新帧。
- **连接不在这里做**（除了【打开相机】顺手替连一次）：设备管理才是连接入口，
  这里的状态点直接反映那边的真实状态。
- 引脚编号与红点是 `render_annotated` 画进底图的（和原工具同一套），
  芯片框与框上编号是矢量层，缩放不糊；只有「存引脚标注图」时才把编号烙进像素。
- 识别结果的字段与「引脚识别工具」一致（`chip_id / id / label / box / pin_count /
  side_counts / flags / method / pins`），两边 JSON 可以互相喂。
- `_flush_cfg()` 里挡了一道 `if not self._inited: return` —— 页面还没走过一次
  `_apply_cfg` 就存盘，会把界面的默认值（比如点大小 1）当成用户设置写进配置文件。

### 算法与模型从哪来

`pintool\` 是从 `PinTool_portable_20261103` **原样复制**的算法目录，一行没改；
`vision\canvas.py` / `vision\pinedit.py` 是同一来源的交互画布与工具条，交互逻辑没改，
只换了配色、去掉按钮上的 emoji，并把工具条加了横排（`horizontal=True`）：

| 文件 | 来源 | 作用 |
|---|---|---|
| `pin_detect.py` / `pin_c/f/t/l/o.py` | 原工具根目录 | V12 主算法 + 各类封装专用算法（C/V 两端件、F 四边 32、T 上下 10、L 两排 3、O 单排 7） |
| `gray_pin\gray_boost.py` | 原工具根目录 | 低分辨率 / 单芯片特写时的兜底通道 |
| `core\pins.py` / `core\yolo_detect.py` | 原工具 `PinTool\core` | 封装层：整板识别、标注绘制、YOLO 推理 |
| `weights\best.pt` | 原工具 `weights` | YOLO 检测模型，类别 F / O / T |
| `vision\canvas.py`、`vision\pinedit.py` | 原工具 `PinTool\ui` | 交互画布、引脚编辑工具条（只改配色、依赖与排列方向） |

`pintool\core\pins.py` 里的相对路径是按「往上两级是项目根」算的，所以目录层级
（`pintool\core\`、`pintool\pin_detect.py`、`pintool\gray_pin\`）不能打乱，
否则它会找不到算法与兜底模块。

依赖（torch 2.8 CPU / ultralytics / opencv / numpy）都在 `runtime\python` 里，
和原工具的包是同一份，不用另装。

  第一次上机先看点【打开相机】后状态行有没有变成「● 取景中 3072 × 2048 x.x fps」。
- 一帧 3072×2048 在 CPU 上 YOLO 约 1~3 秒、引脚识别 0.5~3 秒（首次还要加约 3 秒加载模型），
  期间画面上的进度浮层会转，不是卡死。
- 置信度调得很低时会把焊盘、丝印当成芯片，宁可少检也别乱检。
- 补的点、改的框会**立刻写回 `<图名>_pins.json`**（原工具的行为），
  所以别在只读目录里补点。

### 自定义引脚类别（Y / AA …）

左栏【类别管理】= 引脚类别的注册表。**内置 6 类 O / T / F / C / L / V 永远存在、
永远不能删**；新增类别只是「基础大类 + 每排引脚数 + 一个名字」，识别时转调该大类的
算法、把 n 换成自己的值。

- **只读态点类别不会选中** —— 必须点右上角【编辑类别】进入编辑态才能选、才能增删。
  这是故意的：类别是全局设置，误点一下就改掉会让人以为识别坏了。
- 新增：选大类（T/F/O/C/V/L/**K**）→ 输入名称（**1~3 个字母**，不能重名，`SOP`/`QFP`/
  `OTHER` 是历史别名也占用了）→ 输入每排引脚数。例：`Y` + 大类 `T` + 每排 `14`
  → 标签为 `Y` 的框按 T 算法识别、出 2×14 = 28 点。
- 删除：只对自定义类别可点。删掉后，已存 JSON 里标签为该名的框会回退到**通用算法**
  （点数按图像自适应，不再保证准确），界面上会明说。
- **增删会同步到「测试管理 → 测试程序编写」的「矩形框」列**（候选值现算，
  见第七章那张 7 列表的说明）；已填的文字不会被清掉。
- 权限：这个按钮归功能点 **`vis.kinds`**（不是 `vis.edit`）。操作员默认没有，
  点下去会被拦、给一句"权限不足"并写审计；管理员 / 工程师默认有。

**新增类别不可能影响原类别**，这是构造性保证而不是"测过"：`pin_t.NT=10`、
`pin_f.NF=32`、`pin_o.N_PINS=7` 这些常量一个都没动，`detect()` 只在最前面加了一条
「查注册表 → 命中就带着 n 去调基础算法」的分支，内置 label 查表返回空、走原路。
自测里专门比对了「加 Y 前后内置 T 的每个点坐标完全一致」。

| 大类 | 引擎 | 说明 |
|---|---|---|
| T | `pin_t.detect_T(opt={"n":…})` | 全链路按 n 走，**最稳的一档**；但只探上下两条边 |
| F | `pin_f.detect_F(n=…)` | 四边各 n 个 |
| O | `pin_o.detect_O(n=…)` | 单排 n 个 |
| L | n=3 走 `pin_l`；n≠3 走 T 引擎 | `pin_l` 的 `_to3()` 是三点专属（双瓣焊盘合并按 3 段做），硬套 14 点会把相邻焊盘并错，所以换同族的 T 引擎 |
| C / V | `pin_c.detect_C` | 两端件，每端固定 1 个焊盘，每排只能填 1 |
| **K** | `pin_k.detect_K(opt={"n":…})` | **任意朝向 + 任意 n** 的双排件：自己判「上下两排」还是「左右两排」，不依赖标签、也不依赖图像长宽比。详见下节 |

注册表落在 `data\pin_kinds.json`（只存自定义类别，内置的不落盘），原子写。
**注意**：新类别只是"换 n"，不会让算法学会新封装的光学特征。深度口径、行带阈值、
相位消歧门槛都是按实物标定过的，换一块板/一种封装第一次用时，仍然要在真实图上
看一眼点有没有压在焊盘上（这套算法的原则一贯是「宁可 0 点，也不要数量对、位置错」）。

### K 大类：任意朝向的双排件（2026-11-11 接入）

**为什么另立 K 而不改 T / L**：T 的 `PAIR = ("top", "bottom")` 是写死的，`along_range()`
恒返回 x 范围 —— 整个坐标系里没有"左右"，所以竖放的件不管标签打什么都是 0 点
（2026-10-26 为了压住"T 被误判成 left/right、多出假排"才这么定的）。L 虽然两对边都
试，但 `_to3()` 是"把焊盘合并到 3 段"的三点专属逻辑，于是 `_detect_custom` 里 n≠3 时
又转回 T，还是只探上下。这两个都是实测达标的存量算法，不动；K 把两件事一起换掉。

K 与 T 的三处实质差别：

1. **四条边全评，选相对的一对**：上下、左右各解一次，取「两排都可信 + 综合质量最高」
   的那一对（一对里按木桶效应取差的那排）。方向由证据决定。
2. **行带枚举**：按每个局部峰各生成一条候选带（各自的相对阈值），每条都做一次梳拟合，
   按「平均齿对比度 ÷ 间距不齐度」评分。T 只取全局最亮那一条 —— 一旦本体边缘的横贯
   亮带比引脚亮，那一排就永远丢了（实测 74S020010 的底排就是这样整排 0 点）。
3. **pitch 不靠"铺满"先验**：n 只决定齿数，间距由剖面峰 + 梳拟合搜出来，n=3 和 n=14
   走同一条路。

**深度口径是标定过的，别随手改。** 每根引脚在深度方向常是两段（外侧窄引脚条 + 内侧
宽焊盘块），三种"看着都对"的口径实测各差 20~30px：按「沿边平均亮度最大」会两排各用
一把尺子（y=65 / 416）；按「齿对比度最大」会贴到最外端（64 / 433）；按「行带中点」会
被窄带夹住（75）。正解是**深度范围和行带解耦**：用峰值 10% 的低门限沿齿对比度扩出
整根引脚，再按沿边平均亮度求重心（y=92.3 / 425.1，与视觉中点吻合）。逐齿不再精化 ——
一按亮度逐齿找，外段亮块会把点拽回去。

编号口径与 T/L 一致（1 号 = 先绕那一排的右上角，逆时针一圈），由
`pins._sort_algo_pins` 里 `base == "K"` 的分支走 `_order_l`（它本来就会按 side 分
「上下」/「左右」两支）。**其它自定义类别不受影响**，仍走原来的路径。

**已知限制**：K 不会自己数 n，n 是类别里填的。填小了会少给点（点位仍压在真焊盘上），
填得离谱（例如 14 脚的件填 24）直接 0 点。所以第一次用某封装时，要在真实图上确认
点数 = 2×n 且每个点都压在焊盘上。

## 八、知识库（已接入）

## 八、知识库（已接入）

把资料导进来，问一句话，**给出原文和出处**。注意它不"懂"工艺，只负责把写过的
东西准确地翻出来 —— 这个定位决定了所有设计取舍。

### 用起来什么样

界面是一张**问答卡**（左侧是命中的原文片段，右侧是对话），不是"搜索框 + 结果列表"：

```
┌ 命中的片段 · 17 条 ┐ ┌ ▍RAG 智能问答         ＋ 添加资料  会话 KB-20261110-1502 ┐
│ 01 2.5 筛点的算法  │ │ 你问                                            │
│   对程序里的每一行…│ │   为什么读取不到 T_2                             │
│ 02 2.8 日志怎么读  │ │ RAG 助手                                        │
│   日志：程序第 N 行│ │ ┃ 图上没有这个 label → 记进"缺席"清单，跳过      │
│ …                  │ │ ┃ 依据　2.5 筛点的算法                           │
│                    │ │ 17 段命中 · 1 ms · 看检索过程 · 打开这一节        │
│                    │ │ 原文 · 第 1 / 17 条  ……原文和同页附近……          │
│                    │ ├─────────────────────────────────────────────────┤
│                    │ │ 最近 [为什么读取不到T_2][相机是哪个牌子]  搜索记录 │
│                    │ │ [ 输入问题，回车发送            ] [ 发送 ]        │
└────────────────────┘ └─────────────────────────────────────────────────┘
```

- **开口就问**。下面输入框回车就发，停 280ms 也会自动搜；发送按钮和回车等价；
- **右栏先给一句结论**（标着"RAG 助手"的气泡），下面是原文 + 出处 + 高亮，能当场翻手册核对；
- **搜索记录**：发过的问句自动存进 `data\kb\history.json`，底部一排"最近"胶囊点一下就重问，
  右边【搜索记录】能看全部 60 条、也能一键清空；首页右栏还有"最近问过"清单；
- 左栏是**证据列表**：命中的片段按相关度排，点第 N 条右边就翻到那一段原文；
- 没输入时左栏是**章节速览**（点一下看这一节），右边是开场白 + 资料清单；
- 查不到也走同一套对话流：摆出"你问" + 助手气泡说清**是哪种查不到** —— **不猜**。

### 先给结论，再给原文

原来右栏只摆原文，用户得自己在里面找答案 —— 这是"不够智能"最伤的地方，比排序
不准更伤。现在的做法：

- 在命中的前 5 块里**跨块比句子**（不是每块各出一句，同一块的第 2 句往往更答得上）；
- 挑句看三样：命中词数、（问"为什么"时）原因提示词、是否只是在复述问题；
- 结论句是**原样摘出来的**，不改写、不生成，下面永远跟着原文 —— 摘错了能一眼看出来。

FAQ 那种排版（`2. 改完程序要重新做视觉启动吗 / 不用。程序变了只影响规则…`）有个坑：
问题本身命中词最多，答案却下一句。所以"和问句高度重合的句子"会被直接剔掉。

### 检索：四层，各管一件事

| 层 | 干什么 | 为什么非有不可 |
|---|---|---|
| 词项倒排 | 中文二元组、英文整词 | 型号 / 参数名 / 编号靠它精确命中 |
| 整句子串 | 查询原样再找一遍 | 只靠二元组会把长句拆碎 |
| 口语改写 | 「读取不到」→ 缺席 / 图里没有 / 未识别 / label | 手册写"缺席"，现场说"读不到"，字面一个字都不重合 |
| 问句意图 | 「为什么」→ 加权 日志 / 常见问题 / 缺席 等排查段 | 不然命中的是"假设 T_1 有 12 脚"那种举例 |

**三条硬规矩**（改这几个函数之前先看）：

1. **编号是强信号**。`T_2` 命中一个就放行，不再要求"命中词数占多数" ——
   现场九成问句都是"某个编号怎么了"，它是确定性信号，不是概率信号。
2. **`df=0` 的词不进分母**。查询端切完停用词会残留「到」这类单字，索引端二元组
   根本不产它（"读取不到"只产出 读取 / 取不 / 不到）。让它占分母，长问句必然被判空。
3. **改写词只加分、不判生死**。扩展词只用于召回和挑句，门槛算的是原词；
   否则一句"读取不到"会拉进十几个词，门槛反而更难过。

查询端还会先把"什么/怎么/是/的"切掉再组词（索引端保留全量）。不切的话
"任务号是什么" 会拆出"号是""什是"，能把任何含"是什么"的标题顶上来。

### 检索过程：答不上来时先看这个

回答下面那行小字（`17 段命中 · 1 ms`）点「看检索过程」，展开这一问的全过程：

```
问句   为什么读取不到T_2
词项   读取(11)  T_2(4)  T2(4)      · 括号里是库里有几块含它
丢弃   到                            · 库里没有这个词，不计入门槛
改写   缺席 图里 里没 没有 识别 警告 …  · 10 个，只负责召回，不参与门槛
问法   「为什么」类 → 加权 日志 / 常见问题 / 缺席 等排查段
门槛   命中 1 个词即放行              · 因为问句里有编号/型号
候选   49 块 → 留下 17 块 → 取前 17
前三   2.5 筛点的算法 · 2.8 日志怎么读
耗时   0.70 ms
```

它要能区分三种"查不到"，因为处理方式完全不同：

| 提示 | 意思 | 该做什么 |
|---|---|---|
| 库里没有这些词 | 资料里根本没这个说法 | 换手册上的叫法，或补资料 |
| 都不到门槛 | 沾到了但沾得不够 | 把问句缩短，只留名词或编号 |
| 资料里没有这一条 | 词在库里，但没有一段在讲这件事 | 确实是资料没写 |

### 搜索记录与"日志"是两件事

现场说的"日志"= **我问过什么**，不是切词 / df / 耗时那一串（那是给开发看的，收进
上面那个「检索过程」里了）。所以两者分开：

| | 在哪 | 存哪 |
|---|---|---|
| 搜索记录 | 底部"最近"胶囊、首页"最近问过"、【搜索记录】下拉 | `data\kb\history.json`，最多 60 条 |
| 检索过程 | 回答下面「看检索过程」 | 只在内存里，不落盘 |

**边打边搜的中间态会被吃掉**：敲"相机是哪个牌子"的过程中会先搜到"相机""相机是哪"，
那几条是过程不是记录 —— `push_history` 发现新问句和上一条是前缀关系就直接顶掉，
不然一屏全是半截问题。

### 抽取与切块

| 层 | 在哪 | 干什么 |
|---|---|---|
| 抽取 | `app/knowledge/pdftext.py`、`docxtext.py` | PDF / Word → 带页码、章节的文字 |
| 切块 | `extract.py` | 文字 → 片段（一张表一行一条、一段话不拆开） |
| 索引 | `search.py` | 片段 → 倒排表；查询 → 打分排序 + 挑句子 |
| 存储 | `store.py` | `data\kb\` 下的清单、片段、原件副本、搜索记录 |

**抽取器是手写的，没用第三方库**：软件自带的是精简版 Python，没有 pip，现场机器
也装不了包。PDF 只认**有文字层**的（Word 导出、手册、规格书都属于这类），扫描件
抽不出字会在导入时报"像是扫描件，需要先 OCR"。Word 用标准库解 zip + XML，
标题靠 `outlineLvl` 认（比猜字号稳）。

切块规则：按"文档长什么样"切，不按主题。

| 长什么样 | 怎么切 | 为什么 |
|---|---|---|
| Word 正文段 | 相邻段合并到 400 字上下 | 一句话中间不能断，多带点上下文更好用 |
| Word 表格 | **一行一条**，把表头抄进去 | 不抄表头，搜到"5472"不知道这列是分辨率还是别的东西 |
| PDF 表格行 | 一行一条（靠**列间隙**识别） | 规格书一行一个参数，糊成整页就查不准 |
| PDF 叙述 | 2~5 行一块，不超 260 字 | 保住上下文，又不至于把整页塞进一条 |

表格行切成一句话的样子：`参数：分辨率；MV-CS200-10GM：5472 × 3648`。

### 导入与存放

- 【添加资料】支持 PDF / **.docx** / .txt / .md（`.doc` 老格式先另存为 docx）；
- 导入时把原件**复制一份**到 `data\kb\files\` —— 微信 / U 盘里的文件随时会没，
  只记路径的话过两天整库就空了；
- 同名同大小的文件再导一次 = 覆盖更新，不会重复入库；
- 删资料会连副本一起删，片段全量重建（几百份也就一两秒）。

```
data\kb\
    sources.json     资料清单（名字、类型、页数、片段数、导入时间）
    chunks.json      切好的片段（检索查的就是它）
    files\           原件副本
```

### 已经导进去的

| 资料 | 片段 | 能查什么 |
|---|---|---|
| 测试程序编写与自动测试读取说明.docx | 117 | 七列语义、筛点算法、S 型排序、14 列来源、异常对照 |
| MV-CS200-10GMGC 相机规格书.pdf | 48 | 分辨率、帧率、靶面、曝光、接口、功耗、工作温度 |

库里空着时，进页面会自动把 `docs\` 目录下的资料导进来（首次启动不用手动点）。

### 已知限制（这些是能力边界，不是 bug）

- **不做 OCR**：整页是图、没有文字层的 PDF 抽不出字；
- **PDF 表格靠列间隙猜**：排版特别挤（列挨在一起）的表格可能被当成正文；
- **改写是"查表"，不是真语义**：`读取不到 → 缺席 / 图里没有 / 未识别` 这种
  能翻过去，因为 `_SYN` 里写了；但"相机能拍多快"仍然命中不了"最大帧率 5.9 fps"，
  表里没写的关系它不会自己想到。写型号 / 参数名 / 编号最准；
- **结论句是摘的，不是写的**：句子可能带着上一句的尾巴（"跳过 图上没有这个…"），
  读起来不如人写的顺。好处是每句都能在原文里找到，不会编；
- **索引在内存里**：启动后第一次进页面会重建一次（165 段约 5ms），资料上万段要再优化。

## 九、首页（宣传页）

首页不是干活的地方，是**一页看清"这套东西替人省了什么"**。上排左：系统全景
（19 秒宣传片循环播放，带章节、时间码、进度、四角 HUD）；上排右：6× 效率那几个
数字；下排三张图：单板耗时构成、连续 8 小时良率、六维能力。

### 三块内容

| 位置 | 内容 | 数据从哪来 |
|---|---|---|
| 上排左 | 系统全景：宣传片循环 + 章节名 + 时间码 + 底部进度 | `app\assets\home_reel.mp4` |
| 上排右 | 6.0×、单板耗时、单班产能、漏检率、追溯字段、新人上手（五行轮播） | 常量 `KPI_ROWS` |
| 下排 | 耗时构成（堆叠条）/ 8 小时良率（双折线扫描）/ 六维能力（旋转雷达） | `SEGS` / `Y_MAN·Y_AUTO` / `RADAR` |

**数字是示例值，页脚写明了**（按单板 60 min、8 h 班次测算）。改数字时几处要一起动：
60 → 10 min 才是 6×；8 h 班次 8 板 → 48 板；48 × 10 min = 480 min 正好一个班。
不一起改，一算就露，现场一核对就穿。

### 三个动效（2026-11-10 按用户批注加的）

领导看完提了三条：对比不够突出、曲线是死的、雷达想转。这三条现在都落地了 ——
**只是动，数据和文案一个字没改**。

* **效益表一排一排点名**（`KpiCard._weights`）：每排独占 1.05 s，最后 42% 交叉淡化
  交给下一排，五行 5.25 s 一圈。轮到的行淡红底 + 左侧红竖条、标签大 2 px、
  数值大 3 px 并变成**红色**（旧值压暗一档、仍带删除线）。视觉权重取 `w ** 1.7`，
  让旧行退得快、新行上得晚 —— 不压曲线的话交接时会同时看到两条完整高亮，显脏。
* **良率曲线每 5.2 s 从 0 h 重画一遍**（`YieldCard._sweep`）：扫描头贴着曲线跑、
  竖直虚线 + 轴上的三角游标跟着走，x 轴刻度走到哪格哪格变蓝，左下角有
  "班次 x.x / 8.0 h" 读数；**要等跑到 8 h，右侧 99.3% / 91.8% 才落定**。
  扫描头的 y 用 `_curve_y()` 对三次贝塞尔反解，不是拿数据点线性插值 —— 不然
  圆点会浮在画出来的线外面一两个像素。
* **六维雷达绕中心自转**（`RadarCard`，4.8°/s 约 75 s 一圈）：蛛网、辐条、两个多边形
  一起转；轴名**跟着位子绕、但字永远水平**，对齐方式每帧按当前 cos 重算
  （左半边右对齐、右半边左对齐），否则会压在图上。因为轴名会绕整圈，
  外圈半径由"去掉图例宽度后的一半"和"高度的一半"两头夹定，不能只看高度 ——
  按老算法转起来轴名会跑到卡片外面去。

### 宣传片为什么不用 QMediaPlayer

离线机不保证装了 Qt 的多媒体后端，缺一个插件就是黑屏、还不给提示；`cv2` 本来就是
本项目的硬依赖，直接解帧更稳。细节写在 `app\media\reel.py` 顶部，四条最要紧：

* **缩放在解码线程里做完**，直接缩到"画面矩形 × 屏幕倍率"。界面拿到 1:1 贴，
  不再重采样（一张 1280×720 每帧重采样就是 1~3 ms）；
* **等界面画完再解下一帧**（回执/背压）。不背压的话界面一卡就堆一队过期帧，
  内存和 CPU 一起涨，画面还越来越滞后；
* **片源帧率高于输出帧率时必须丢帧**。片源 30 fps、输出 20 fps 时，老写法
  "读一帧抛一帧"等于**慢放到 0.66 倍速**（19 秒的片子放 29 秒）。现在按墙上时钟
  算"该播到第几帧"，落后多少就用 `grab()` 丢掉多少（只挪指针，比 `read()` 便宜）；
* **章节与时间码按解码器上报的帧号算**，不用墙钟 —— 实测墙钟会跟画面差三四秒
  （解码有快有慢、暂停、循环都会把墙钟带偏）。

画面边缘做了白化羽化，不套黑色显示器边框：源片底色本来就接近白，羽化之后
3D 线稿像是"浮"在白卡上；套黑框会跟浅色主题打架。

换片子要重新对 `CHAPTERS`：先跑帧间差分找转场峰值，再逐点抽帧核对分镜标题。
现在这条 19.3 s 的七段是 3.2 / 5.1 / 7.6 / 9.5 / 11.6 / 17.0，手写估计差好几秒。

### 动画只在看得见的时候跑

页面切走就停表 + 暂停解码；三张图不进静帧，各留一个低频循环（效益表 20 fps、
曲线 20 fps、雷达 20 fps、宣传片 20 fps）。卡片要声明 `WA_OpaquePaintEvent`：
不声明的话 Qt 每帧会先把**父窗口**的工作区渐变重画一遍（1100×742），25 fps 下
这一项就够多烧半个核。

实测（1360×830、dpr 2）：进程 CPU 约 0.69 核，播放倍速 0.95（片源 30 fps、
输出 20 fps，靠丢帧追平）。大头是 cv2 解码（它自己开多线程）—— 丢帧等于多解
几帧，所以 CPU 比"慢放"时高，但换来的是播放速度跟墙上时钟一致。目标机是
GPU 高配，这个量级可以接受。

## 十、数据管理（布局版，未接数据）

> 这一轮**只做布局**：五个子页的骨架、工具栏、表格、波形区、图表全部摆好，
> 但没有取数逻辑 —— 表格留空、指标写「—」、波形与统计图是**示意形状**（页面上
> 都挂了「示意」角标）。用户明确要求"等有数据和测试结果了再接具体内容"，
> 接的时候只改各页的 `reload()`，布局一行不用动。

08 系统管理那边管的是"谁能用"，06 数据管理这边管的是"测出来什么"。按用户的话，
**数据管理更侧重各采集信号的图形展示，支持多组任务的波形对比（电压、时钟、总线），
比如同一块板修前和修后**。

### 五个子页

| 子页 | 干什么 | 布局要点 |
|---|---|---|
| 结果查询 | 哪块板、什么时候、过没过 | 筛选条 + 结果表（10 列）+ 右侧任务详情（7 个字段 + 4 格指标） |
| 波形回放 | 修前 / 修后叠着看 | 左任务清单 + 右三泳道波形 + 光标读数 |
| 报表生成 | 按模板出一份给客户的报告 | 左模板列表 + 右参数卡（时间/批次/格式/包含/目录）+ 预览位 |
| 数据导出 | 把数据拿成 Excel / CSV | 上排「范围与内容」「输出与执行」，下排导出历史 |
| 批次统计 | 是不是在变差 | 五格指标 + 良率趋势折线 + 缺陷分布横条 + 批次汇总表 |

### 波形回放怎么摆的

这是这一页的主场，所以单独说：

- **三条泳道**（电压 VCC_3V3 / 时钟 CLK_24M / 总线 I2C_SDA）上下排，跟示波器一个读法
- **量程一样（0~3.6 V）就等分**，不按各自值域自适应 —— 上下等宽才比得出"哪条抖得凶"
- **修前（红）与修后（绿）叠在同一泳道**：不是并排两张图。并排要来回扫眼睛，
  叠在一起是"同一时刻的两条线"，差异（纹波、振铃、丢位）直接落在同一个 x 上
- 纵向留 8px 余量：修前时钟有振铃，贴边画会被裁
- 右上角常挂「示意波形 · 未接入采集数据」，**别让人把示例当成真数据**

波形是自己用 QPainter 画的，没引 pyqtgraph：现场离线机没 pip，多一个依赖多一处
装不上的风险；600 点/条的折线重绘不到 2 ms，够用。真到百万点再换库，那时也只换
`_series()` 一处。

### 只做布局，所以这些是空着的

- 表格 0 行，下面一句说明写清"接数据后长什么样"
- 指标全写「—」，不编数字
- 图表画坐标系 + 示意曲线，标题行标「示意」

### 1100 宽怎么挤下的

1360 下很宽松，1100（项目的最小窗口）就得抠：

- 结果查询的筛选条：标签降到 9pt、控件按"刚好够用"给宽度；**「共 N 条」挪到表格
  标题行** —— 夹在筛选条最右边会先把【查询】【重置】挤到重叠
- 波形回放：去掉「缩放 − ＋」两个按钮（画布支持滚轮缩放，底部有一句提示），
  「导出波形图」缩成「导出图」
- 导出页表格列宽压到 690，1100 下不出横向滚动条
- 结果查询的表格 10 列在 1100 下仍要横向滚动 —— 列都有用，宁可滚也不裁字

### 这一轮踩的坑

1. **QWidget 上写 `setStyleSheet("background:…; border:1px dashed …")` 画不出预期**
   —— 默认 `paintEvent` 不画样式表里的背景/边框，画出来多大全看它高兴。预览框
   最初就是这么写的，结果虚线只包住两行字、没撑满卡片。改成自绘 `PreviewBox`。
   指标条之间的竖线同理，换成 QLabel。
2. **换行的 QLabel 会把卡片高度算错**：`sizeHint` 按"理想宽度"估行数，卡片窄一点
   就要多一行，而外层还按老高度摆位置，最后一行就压在卡片边框上（系统设置页踩过
   同款）。卡片内的说明一律 `setWordWrap(False)`，文案宁可短。
3. **「参数卡 + 预览卡」上下排时，空间不够会先压参数卡** —— 压到比 `sizeHint` 还矮，
   最后那行按钮就骑在边框上。`setMinimumHeight` 是一根硬底，压不过去。
4. **`self.show` 不能当变量名**：WaveCanvas 里本想存"显示哪几条"，一取这名字就把
   `QWidget.show()` 顶掉了。改成 `self.vis`。

## 十一、系统管理（已接入）

08 系统管理分两块：**登录体系**（谁在用这台机器）和**治理功能**（五个子页签）。
账户和权限都是**本地**的，不联网、不加密钥，拷走整个目录换台机器照样能登。

### 登录：进来先是首页，模块要登入才能开

这是用户口述改的，不是原稿的"双击直接进首页"。行为按用户原话：

- 双击进来落在**首页**，此时是"未登入"状态：顶栏右侧显示 `?` + 「未登入」+ 【登入】【注册】，
  左侧 02~08 每一项右边挂一把小锁（`NavItem.set_locked()` 自绘的，不是图标文件）
- 点 02~08 会弹「请先登入」，两个按钮【稍后】【去登入】，选【去登入】直接开登入框
- **注册**：用户名（2~20 字，不能用 `空格 \ / : * ?`）→ 角色 → 身份证后 6 位 → 密码 + 确认密码
- **登入**：下拉选已注册的用户名 → **角色自动带出**（只读，改角色要去用户管理）→ 输密码
- **忘记密码**：登入页最下面那行 → 选用户名 → 填注册时的身份证后 6 位 → 设新密码 →
  回登入页用新密码登入（重置成功不会自动登入，按用户要求"回登入界面输入新密码"）
- **关掉工具就退出账户**：会话只活在内存里（`auth.Session`），进程没了就没了；
  `closeEvent` 里显式 `logout("退出程序")` 写一条审计，下次打开必须重新登入

密码与身份证后 6 位都过 PBKDF2-HMAC-SHA256（12 万次迭代、**每个账号 16 字节独立盐**），
比对用 `hmac.compare_digest`（常数时间，不让计时泄露前缀）。库里存不出明文，
`users.json` 里能看到的就是 salt 和 hash 两个十六进制串。

连错 5 次锁 5 分钟（可在系统设置里改）。提示会写"再错 4 次锁定"，锁定期内告诉还剩几分钟 ——
不写清楚的话现场只会以为密码错了。

### 五个子页签

页面在 `app/pages/system_page.py`，子页各一个文件，共用件在 `sys_common.py`。

**1. 用户管理**（`sys_users.py`）

列表：用户名 / 角色 / 状态 / 创建时间 / 最后登入 / 审计记录。按钮：新建用户、修改角色、
重置密码、禁用、删除。

- 用户名唯一（比较时不分大小写），建完立即能登
- 禁用保留历史审计，状态列显示"已禁用"；删除只允许**没有任何审计记录**的账号 ——
  有记录的一律拒绝并提示"改成禁用"，因为删了账号，审计里那些行就成了无主记录
- 选中自己时：改角色 / 禁用 / 删除全灰掉（不能自己把自己锁在外面）
- 系统里最后一个管理员不能降级、不能禁用、不能删

**2. 角色权限**（`sys_roles.py`）

23 个**功能点**（不是菜单）排成矩阵：管理员 / 工程师 / 操作员 × 23 个勾。按模块分组，
每项后面跟一句人话说明（"查看设备与参数"、"连接 / 断开设备"）。

- 保存前先列出**这一轮改了什么**（"操作员：data.export 开 →"），确认了才写盘
- 写完立即生效：`session.can()` 每次都**现查**矩阵，不缓存副本，所以不用重新登入
- 取消管理员自己的 `sys.role` / `sys.user` 会额外警告一次（等于把治理权交出去）
- 「视觉定位」这一组是三个点：`vis.view` 看画面 / `vis.edit` 调参数与运行识别 /
  **`vis.kinds` 类别管理**（新增、删除引脚类别）。类别管理单列一个点，是因为它改的是
  "哪个标签走哪套算法"，影响面比调参数大 —— 默认管理员和工程师有、操作员没有

**3. 审计日志**（`sys_audit.py` + `audit.py`）

只追加、不可删、不可改。每条记录带 `prev` 指向上一条的哈希，`h = sha256(seq|ts|user|role|action|target|result|detail|prev)`，
整条链从 `GENESIS`（64 个 0）串起来。

- **【完整性校验】** 从头重算整条链，报"3 条记录的哈希链首尾相连，没有断点"；
  被改过就报"本年 11 月文件第 42 条，本条内容与哈希不符（被改过）"——
  定位到文件 + 行号，而不是只说一句"校验失败"
- 按月一个文件（`data\audit\audit-YYYYMM.jsonl`），写一条 `flush + fsync` 一次；
  半行坏只影响最后一条
- 与业务数据**分开存**（`data\audit\` 不是 `data\` 根下），备份恢复也不覆盖它
- 筛选：关键字（用户 / 动作 / 对象 / 说明）+ 结果（全部 / 成功 / 失败）；导出 CSV 用
  `utf-8-sig`，Excel 直接打开不乱码

**4. 备份恢复**（`sys_backup.py` + `backup.py`）

包名 `FULL-YYYYMMDD-HHMM.zip`，同一分钟再点一次自动加 `-2`。

- 包里有一份 `MANIFEST.json`，记每个文件的 sha256 和大小；校验时**逐文件比 sha256**，
  不靠 zip 自带的 CRC —— CRC 只能发现传输坏了，发现不了"把包整个换成另一个能解开的包"
- 恢复前**先自动备一份当前状态**（`BEFORE-RESTORE`），恢复错了还能回去
- **恢复不覆盖 `data\audit\`**：否则"恢复到三天前"就把这三天的审计抹了，
  而审计的意义正是"删不掉"
- 恢复后重新载入 users / roles / settings，并**强制登出**（权限可能已经变了）
- 自动备份：默认每日 02:00，工具开着的时候到点执行；当天已经备过就不重复
  （`settings.backup.last_auto` 记日期）。备份失败只告警，上一份可用备份不动
- 保留策略：最近 7 日备 + 4 周备（按日期留最新、按 ISO 周留每周最新），超出的删掉

**5. 系统设置**（`sys_settings.py`）

四张卡：安全策略（最短位数 / 必含数字 / 必含字母 / 连错几次锁 / 锁多久）、
备份策略（每日自动 / 几点 / 留几份日备 / 留几份周备）、审计与数据（条数 / 文件数 /
首末时间 / 数据目录，可选中复制）、版本信息。

保存前列出全部改动（"密码最短位数：6 → 8"），保存即写审计。
默认策略：**6 位 + 必须含数字**，连错 5 次锁 5 分钟。

### 权限是怎么拦住的

三道闸，缺一道就有漏网：

1. **点导航**：`select_module()` 是唯一入口。未登入 → `_prompt_login()`；
   权限不够 → `C.tell` + 写一条 `FAIL` 审计（"越权访问被拒绝"），不放行
2. **点按钮**：`PermGuard`（`QObject` 事件过滤器）装在按钮**自己**身上，
   `MouseButtonPress` 时判权限，不够就把事件吞掉 —— 按钮照样画出来（灰着），
   但点不动。运动控制那块是整块 `deep=True`，连子孙控件一起装，
   否则从输入框按 Tab 也能摸到
3. **页签**：5 个子页签各自声明所需功能点，没授权的不生成（不是生成后隐藏）

功能点 → 模块的映射在 `auth.MODULE_POINTS`，`home` 是 `None`（首页谁都能看）。

### 数据都存哪儿

```
data\auth\users.json      账号（salt + hash，无明文）
data\auth\roles.json      角色 → 23 个功能点
data\settings.json        安全策略 / 备份策略
data\audit\audit-*.jsonl  审计（只追加）
data\backup\FULL-*.zip    备份包
```

`data\auth\` 空着的时候程序照常启动，只是没人能登入 —— 第一个账号要自己注册。
忘了密码又忘了身份证后 6 位，只能手工删 `users.json` 重来（责任在管理员，所以身份证
后 6 位要提前留档）。

### 这一轮踩过的坑

**1. 密码框旁边整片白 —— 无选择器的 `setStyleSheet` 会向下覆盖**

登入卡片的基类里写过 `self.setStyleSheet("background: transparent")`，想给卡片一个透明底。
没有选择器的写法会**递归作用到所有子控件**，按钮自己的 QSS 被顶掉，于是白底白字、
看起来"只剩一个边框"。要透明就写 `QWidget#authCard { background: transparent; }`，
或者干脆别设。

**2. 页签都建好了，界面上一个都没有**

子页签是用 `move()` 手动摆的（要居中，不能用布局），窗口**已经显示之后**再新建的子控件
默认是隐藏的 —— 不在布局里就不会被自动 `show()`。`_build()` 末尾必须逐个 `tab.show()`。

**3. 改一次权限，人就被甩回"用户管理"**

权限变了要重建页签（原来没权限的这次可能有了）。重建时得带上当前子页 key
（`_build(keep=...)`），否则一律回到第 0 页。

**4. 程序退出码 127、一行输出都没有**

`paintEvent` 里用了 `QPointF` 而导入那行被顺手删了。PyQt5 里**画图函数抛异常直接 abort**，
Python 的 traceback 根本来不及打，缓冲输出也一起丢。最后靠
`qInstallMessageHandler` + 自定义 `QApplication.notify` 才看到那行 `NameError`。
后来 `faulthandler` 只能给线程栈，看不到这个。

**5. 卡片矮一截，最后一行压在底边框上**

`sizeHint` 只是"建议"：布局空间不够时会一路压到 `minimumSizeHint`，而且**不报错**。
系统设置页那四张卡就是这么矮掉 17~34 px 的。这个页面里的说明文字还是 `reload()` 之后
才填进去的（建卡时是空串），外层布局按空标签算过一次高度就再也不跟着长。
解法是 `setMinimumHeight()` —— 布局必须服从最小高度。另外把几行"数据行"
（审计条数、时间、数据目录）改成不换行：一换行行数就随宽度变，高度算不准。

**6. 停在首页，面包屑却写"系统管理 / 用户管理"**

登入/登出会让系统管理页整页重建，重建里 `_select()` 会把 `sub_changed` 重新发一遍，
`_on_sub_changed()` 不判当前模块就照写。加一句"这个模块正显示着吗"就好了。

**7. 测试脚本把假账号写进了真实 `data\auth`**

`settings` / `roles` / `users` 三个 store 都是**导入时**就建好单例、把路径存进 `self.path`
的，只改模块常量 `USERS_PATH` 没用。自测脚本必须连单例的 `path` 一起改再让它重读，
否则测试一跑就把 eng/op 这些假账号写进交付目录。发现时已经写进去了，
`data\auth\users.json` 和 `data\settings.json` 两个文件已删掉恢复成空库。

## 十四、几条约定

**1. 配色只改 `theme.py`**

所有颜色、字号、尺寸都从那里取，不要在各处写死十六进制值。

2026-11-10 整体换成**浅色版**（领导批准的方案）：浅蓝底 + 白面板 + 深蓝强调。
- 底：工作区 `#eef4fa`、侧栏 `#dce8f5→#ccdeee`、顶栏白、面板白
- 字：正文 `#1f3750`、次级 `#5b7186`、弱化 `#8ba1b5`、页头大标题 `#0b2e5c`
- 强调：`AMBER / AMBER2 / AMBER_DIM` 三个**变量名没改**，值换成了深蓝三档
  `#1b57a0 / #2e74c4 / #6d94be`。全局 200 多处 `theme.AMBER` 都是"强调色"语义，
  改值即可；三档明度必须拉开，不然按钮、描边、编号会糊成一片
- 状态色压深一档（白底上原来那套给黑底调亮的会发飘）：OK `#1e8f56`、WARN `#b0740f`、
  BAD `#c0392b`、CYAN `#0f8b84`
- **蓝白格子已去掉**：`GridCanvas` 只留页头一条 132px 横向蓝渐变（`HEAD_GA/GB/GC`），
  往下淡出到底色。浅色下再铺 34px 网格，屏幕会显得脏

换色时留意三处「不是光靠改色板」的地方：
`widgets.paint_panel`（白卡靠边框+顶部蓝高光+四角角标撑质感）、
`widgets.paint_module_head`（编号描边要更实、填充要更淡）、
`main_window._style_titlebar`（浅色版要把 DWM 深色模式**关掉**，否则白底白字）。

**局部 `setStyleSheet` 必须带选择器。** 没有选择器的规则（`"background: transparent"`）
会向下传给所有子孙控件 —— 包括 `QComboBox` 弹出列表的 viewport：popup 虽然是独立的
顶层窗口，QObject 父链还连着 combo，于是白底被刷成透明，下拉一弹出来就是**黑底灰字**，
几乎看不清（2026-11-11 踩过，`Workspace.stack`、`DeviceModulePage.stack`、`widgets.Panel`
三处都有这行）。写成 `"QStackedWidget { background: transparent; }"` 就只作用于自己；
`Panel` 那种 `paintEvent` 自绘的面板根本不需要它。弹出列表的样式统一写在
`theme.controls_qss()` 的 `QComboBox QAbstractItemView` 里，别在各页另写。

**同一个毛病还会把 tooltip 刷成黑底。** tooltip（Qt 内部的 `QTipLabel`）也算"子孙"，
祖先身上那条没选择器的 `background: transparent` 会让它连底都画不出来 —— 屏幕上就是
**黑底 + 深蓝字**，几乎看不清（2026-11-16 用户报的就是这个）。全工程这种写法有一百多处，
逐个改风险大，所以 `theme.install_tip_guard(app)` 在**每个 tooltip 显示时**给它自己挂一条
`TIP_QSS`（白底 `#ffffff` + 黑字 `#000000` + 淡蓝描边）：自己身上的规则优先级最高，
祖先盖不掉。启动时在 `main.py` 调一次，`theme.qss()` 里的 `QToolTip` 规则仍保留做底色。

写这层时有三个坑：① 只 `new` 过滤器不 `installEventFilter` 是不会有事件的；
② 实例要留引用（模块级 `_TIP_GUARD`），否则 Python 一回收过滤器就没了；
③ 光在 `Show` 上补不够 —— Qt 复用同一个 `QTipLabel`，每次显示前会把它的 styleSheet
重置成占位的 `"/* */"`，所以 `Show / Polish / StyleChange` 三个点都要补（幂等判断）。

**2. 加一个模块**

- `app/modules.py` 里加一项（`key` 是稳定标识，改名字不要改 key；`ready` 决定面包屑显示已接入还是待接入）
- 需要新图标就在 `app/icons.py` 的 `_SHAPES` 里加一条 24×24 路径

**3. 接一个模块的真实页面**

在 `app\pages\` 下写页面类，然后在 `main_window.py` 的 `Workspace.__init__` 里按 `key` 换成真实页面，并把 `modules.py` 里对应项的 `ready` 改成 `True`。其余模块不受影响。

**4. 为什么界面全是 QPainter 画的**

原型那套渐变、左侧色条、描边大编号用 QSS 复刻要走一堆属性选择器和 `unpolish/polish` 才生效，自绘反而准。所以 `widgets.py` 里是 QPainter，不是 QSS。

**5. 尺寸按 CSS 像素写**

这台机器物理分辨率 2880×1800、系统缩放 200%，Qt 的逻辑坐标是 1440×900。所有尺寸按原型的 CSS 像素写就行，Qt 自动放大 2 倍渲染，不要自己乘缩放系数。

**6. Python 运行时和依赖都是拷过来的**

`runtime\python` 从 `PinTool_portable_20261103\python` 整份复制；`pintool\` 从同一个包的算法文件复制；`libs\` 和 `MvImport\` 分别从 KZQ、TZ、XJ 复制。**原工具目录一个字节都不动**，包括不往 PinTool 的 python 里装任何包 —— 那份包有 md5 指纹，动了就没法证明算法没变。

要装新包，装到 `runtime\python` 这份副本里。
